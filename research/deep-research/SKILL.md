# 深度研究（Deep Research）

一个问题进来。一份研究设计、并行的研究线、对抗式审查、一篇可引用的文章出去。

这套流程存在，是因为一次作答有三个长提示词治不了的失败：它停在问题最易得的那种读法上，因为循环里没有谁在问"问题自身的提法排除了什么"；它陈述无人能溯源到页码的断言；它没有对手——循环里没有谁专门负责找出论证最薄弱的承重句。

本 skill 补上这个结构。你是**协调人**。你不亲自搜集材料——你设计、阅读返回的东西、判断、写作。研究员在各自独立上下文里工作，你的上下文留给读他们的产出。审查员在每条结论被带走之前攻击它。

下面的规则是硬性的，每一条都是为了挡住一个具体失败。规则重要处都给了理由；若你发现自己想绕开某条，该重读的正是那个理由。

## 何时使用

- 用户要求深度研究、系统调研、文献综述，或对某个有争议领域做综述。
- 问题确有多解（假设、方法、理论框架、分期之争），用户要的是摆开而非平均。
- 产出要发表、答辩、被引用或用于支撑决策，可溯源性重要。
- 用户想知道一个文献体系*没有*说什么——缺口、缺席的声音、领域不问的问题。
- 一次作答看似可信但无法验证，用户宁要一个慢而可查的答案。

## 何时不用

- 单个事实、定义、日期、查证。直接回答。
- 无研究问题的编码或文件操作任务。
- 用户要快速观点或头脑风暴，不是要一个被辩护过的结论。
- 用户递来文档且问题已被该文档回答——读文档。
- 用户需要无人值守、带崩溃恢复和界面的多小时运行。本流程在对话中逐轮推进；那是专门应用的领域，不是本 skill。

## 三个角色

| 角色 | 谁 | 做 | 不做 |
|---|---|---|---|
| **协调人** | 你，主会话 | 设计研究、选研究员、写计划与结论、处置每条异议、裁决终稿、对用户负责 | 检索网络、通读原始材料、做研究员的任务 |
| **研究员** | 子代理，一卡一个 | 在独立上下文里完成一个任务，交回交付物＋带定位的 findings | 规划研究、评判别的线、写节点结论 |
| **审查员** | 子代理，计划时选定 | 先攻击结论的事实与推理，再在*全新*会话里点出结论拒绝的可能与留下的缺口 | 扩写报告、润色文字、自行开新线 |

审查员身兼两职，因为只查证据的批评者只是半个审查员：一个论证可以内部自洽、出处齐全，却错在没考虑的东西上。

## 节点，与节点之图

一个**节点**是一次完整研究：一个问题、一份计划、若干卡、一个结论、审查、以及关于分叉的决策。用户的问题就是根节点。

凡问题容许真正不同的答法——对立假设、另一套方法、不同理论框架、另一立场的读法、不同的拆解方式、对问题本身的批判——都是一个**分叉（fork）**。每个选项成为自己的节点，有自己的计划、研究员和审查员。被多个选项共同指向的节点，或为把多个已完成节点一起带向前而开的节点，是**汇合（join）**。

图一层层长。当一层的每个节点都完成，你**调和（reconcile）**这一层：把选项开成节点、把走到同一处的线汇合、记录节点间关系。然后下一层开跑。

第一次调和之前先读 `references/06-graph.md`。

## 七个阶段

每个节点跑同一套例程。每个阶段有一份文件，执行前先读。

| # | 阶段 | 你产出 | 必须过的关卡 | 先读 |
|---|---|---|---|---|
| 1 | **计划** | `plan.md`：设计、卡、覆盖表、本设计已见的分叉、审查员人选 | 用户放行；**Coverage** | `references/01-plan.md` |
| 2 | **任务卡** | 每卡一个文件夹，含交付物与 typed findings | 每条发现过 **Citation** | `references/02-cards.md` |
| 3 | **结论** | `synthesis.md`——修订后为 `synthesis-N.md` | **Angle**、**Calibration** | `references/03-synthesis.md` |
| 4 | **批判** | 一份审查，实质问题入账 | 问题被记录，而非藏在行文里 | `references/04-critique.md` |
| 5 | **处置** | 每条实质问题恰好一个处置 | 无实质问题悬空 | `references/04-critique.md` |
| 6 | **可能性审查** | 未走的另类可能与缺口；然后分叉决策 | 每个缺口有处置；每个提案有归宿 | `references/05-possibility.md` |
| 7 | **分叉决策** | ≥2 选项的决策，或明确的"无分叉" | 每个可能恰好出现一次 | `references/05-possibility.md` |

阶段 4–5 循环：修订稿回到同一位审查员，直到没有实质问题或修订预算用尽。之后跑阶段 6。

终稿在六关卡之上加 **Taxonomy** 与 **Weaving**（见"六道关卡"）。

所有节点关闭后，run 以四阶段报告收尾。读 `references/07-report.md`。

## 本 skill 的路径

下面的命令把脚本写作 `$SKILL_DIR/scripts/...`。每次会话设一次，指向本 skill 自己的目录——
即持有本 `SKILL.md` 的目录——之后任何 cwd 下都能用：

```bash
SKILL_DIR="<deep-research skill 目录的路径>"
```

## 逐步循环

1. **建 run。** 与用户确认问题与限额，建 run 目录与账本：

   ```bash
   python3 "$SKILL_DIR/scripts/scaffold.py" <project> --question "<问题>"
   ```

   读 `references/01-plan.md`。
2. **写节点计划。** 写 `plan.md`、填覆盖表、记录分叉，然后：

   ```bash
   python3 "$SKILL_DIR/scripts/check.py" <project>
   ```

   派发任何东西之前修掉全部 P0 与 P1。
3. **获批准**（审批开启时）：用平实语言向用户展示设计——查什么、谁做什么、刻意不做什么——然后等待。
4. **派卡。** 一卡一个子代理，不超过并行限额。每卡拿 `references/08-prompts.md` 的卡提示词加自己的任务。读 `references/02-cards.md`。
5. **写结论。** 动笔前完整读每份交付物。更新 `sources.md`。读 `references/03-synthesis.md`。
6. **审查、处置、修订。** 派审查员。记录问题。逐条处置。循环到干净或预算用尽。读 `references/04-critique.md`。
7. **可能性审查。** 同一审查员、新会话，点名结论没采纳什么、留了什么没补。处置缺口；然后做分叉决策。读 `references/05-possibility.md`。
8. **调和本层。** 开节点、汇合、记关系。读 `references/06-graph.md`。
9. **报告。** 综述、初稿、独立审查、终稿。读 `references/07-report.md`。

每个阶段后更新 `run.json`。它是唯一持久状态；会话中途死掉，恢复靠它。开节点、汇合、
推进状态、记决策与开销都用 `python3 "$SKILL_DIR/scripts/node.py" <project> <子命令>`——
手改 `run.json` 仍然允许，但脚本会把状态机与"一个可能只开一次"这类规则挡在你前面。
随手可以用 `python3 "$SKILL_DIR/scripts/status.py" <project>` 看 run 走到哪一步、有没有停滞。

## 硬规则

1. **交付物是文件，不是消息。** 每个结果——计划、发现、问题、处置、决策——写进 `plan.md`、`findings.json` 或 `run.json`。`check.py` 校验它力所能及的部分：文件存在、schema 成立、每条实质问题有处置、每个选项有一个归宿、定位符可解析。它验证不了行文好坏。聊天里的散文什么都不记录也什么都恢复不了；会话死了，活下来的只有文件。

2. **事实带定位符；其余说清自己靠什么。** `claim_type` 标明断言是事实、推断、诠释还是规范性判断。`fact` 必须有 `source_file`（或 `doc_id`）加 `quote`——指不到的东西，是穿着事实外衣的推断。推断、诠释、规范性判断可以没有文件，但必须写 `basis`：它依赖的前提、立场或一般知识。无论哪种，绝不把断言安在没人打开过的著作头上。

3. **每条实质问题恰好一个处置。** revise、correct、rebut、concede、covered、park 或 branch。沉默不是处置，"我在正文里回应了"也不是记录。反驳（rebut）是审查员有权拒绝的说法。

4. **缺口留在自己的节点里。** 可能性审查分开两件相像的事：*缺口*是任何回答该问题的线都必须补、且在这里补的东西；*未走的可能*建立在别的前提下，成为新节点。把缺口推给子节点，就是没人补的缺口。

5. **一个可能只开一次。** 记录分叉前先查 `paths.md`。若某节点已在追它——无论从哪个框架、哪层深度——新提案是 `covered`，不是新选项。这条规则防止研究图把同一问题换四个名字研究四遍。

6. **用户的问题不是你的改写对象。** 若研究显示问题建立在混淆或意识形态前提上，那是正当的发现——但消解用户的问题改变了他们所问的东西，交付前需要他们明确同意。

7. **审查未清不得交付结论。** 卡、审查或必需的修订未完成时，工作结论留在内部。中途被问的人得到的是进度，不是答案。

## 故障、重试与降级

网络故障与研究卡死是真实运行里反复出现的事（本节每条都有实战出处）。原则：**先重试、再换路、后降级，每次都留痕，绝不静默放弃，也绝不无限重试。**

- **子代理派发失败**（上游 502、超时、被取消）：同一张卡重试至多 2 次。两次仍失败，由你（协调人）按无子代理纪律亲自执行该卡——一次一卡、事后照样写交付物与 `findings.json`——并在 `run.json` 该节点下记 `card_note`（哪个卡、失败原因、由谁执行）；终稿的方法说明必须披露这一降级。
- **用户限定了子代理数量**：把上限记进 `limits`（`parallel`）或 `consent.note`，超出上限的卡由协调人执行或排队，同样用 `card_note` 留痕。
- **网络抓取失败**：换方法再试，不要对着同一工具反复撞。实战验证过的降级链：内置抓取工具（WebFetch 类）失败 → `curl -sS -A "Mozilla/5.0" --max-time 25 "<URL>"` 重试 1 次 → 仍失败则记 `citation_state: "unreachable"` 并写明尝试过什么。同一来源连续 2 次失败就列为 declared gap，不再重试。
- **会话中断**：`run.json` 是唯一恢复点。恢复按 `references/09-ledger.md` 的"恢复"一节；`python3 "$SKILL_DIR/scripts/scaffold.py" <project> --resume` 重建派生视图并点名第一个非终态节点，`--resume --node <id>` 只重建该节点并报告它该从哪个阶段接手。**中断会话遗留的材料（半成品交付物、抓来的源文件）必须逐字核对后才能引用**，并注明它来自中断的会话。
- **怀疑卡死**：`python3 "$SKILL_DIR/scripts/status.py" <project>` 查看各节点所处阶段与账本新鲜度；非终态且长时间未更新的节点会标警示。停滞超过一次对话的自然时长，向用户报告现状与可选动作（继续等待／降级执行／放弃该节点记 `failed`），不要无声挂起。

## 磁盘布局

```
<project>/research/<run-id>/
├── run.json                 # 账本：限额、节点、决策、问题、同意
├── question.md              # 问题原话，不改写
├── graph.md                 # 每层调和后重写
├── paths.md                 # 每个可能及其归宿
├── nodes/<NN-slug>/
│   ├── node.md              # 本节点在图上的位置
│   ├── plan.md              # 设计：卡、覆盖表、分叉
│   ├── cards/<card>/
│   │   ├── <deliverable>.md # 研究员的交付物
│   │   └── findings.json    # typed、带定位的发现
│   ├── synthesis.md         # 结论；之后 synthesis-2.md、…
│   ├── review-01.md         # 批判审查，一轮一份（closed 必需）
│   ├── possibility.md       # 可能性审查（closed 必需）
│   └── sources.md           # 本节点全部文本所依赖的文件
└── final/
    ├── <run>-survey.md      # 每节点一节
    ├── <run>-draft.md       # 文章初稿（独立审查前）
    ├── <run>-review.md      # 独立审查（done 前必需）
    ├── <run>-final.md       # 裁决后的文章
    └── sources/             # 终稿引用的一切
```

## 在你的 harness 里派发子代理

流程对环境只有一项要求：能在**独立上下文**里跑一个任务并拿回结果。各家 agent harness 都有某种形式的这种能力；`references/08-prompts.md` 的模板可以粘进任何一家。

- **ZCode** — 用 `Agent` 工具、`subagent_type: general-purpose`，一卡一调用，一条消息里多个调用即并行。各给各的提示词；不依赖共享上下文。
- **Claude Code** — 同样方式用 `Task` 工具。
- **其他 harness** — 用任何能派出隔离的单一目的 agent 的接口。只要能收系统提示与任务就够。
- **无子代理能力** — 由你自己在本会话中逐卡执行，并写进 `run.json`（`"independent": false` 加 `independent_note`）。这是唯一豁免"作者不能审自己"的情形：审查照样跑，但产出在报告方法说明里标注 **self-review**。由于自审失去了独立可能性审查所依赖的新鲜视角，可以**把批判与可能性审查合并为一轮**——并在说明里写明。研究仍然结构化、可引用；失去的是上下文隔离与审查独立性，读者有权知道自己读到的是哪一种。

并行度：每节点同时在飞的研究员派发至多 3 个，节点同时在飞至多 3 个。只有用户开口才提高——每次派发都是一个完整上下文、一笔完整账单。

## 成本，以及如何收敛

诚实的估算，因为这套流程很贵，用户应当先知道：

| run 形态 | 研究员派发 | 审查员派发 | 大致量级 |
|---|---|---|---|
| 1 节点 4 卡不分叉 | 4 | 2（批判＋可能性） | 一次坐完 |
| 3 节点各 4 卡、各 1 分叉 | ~16 | ~8 | 数次坐完 |
| 30 节点（默认预算） | 120+ | 60+ | 数天挂机，真金白银 |

上表的量级是派发**次数**，不是钱。真实开销要记账才知道：每完成一批派发就

```bash
python3 "$SKILL_DIR/scripts/node.py" <project> spend --node <id> --tokens N --calls N --usd F --what "两卡+一轮审查"
```

之后 `python3 "$SKILL_DIR/scripts/status.py" <project> --cost` 报的就是实测值，并在预算
逼近上限时给出预警。没记账时它只报规模并说"未记录"——它不会拿系数替你编一个数字。

每次派发都是完整上下文。两个杠杆，按效果排序：

- **`--depth`**——每层都乘节点数。"一个问题答好"，depth 1 往往就是诚实答案；depth 3 留给框架真正相争的问题。
- **每节点卡数**——一张卡是一个研究员会话。两件事捆一张卡更便宜也更糟；要砍就砍范围并声明缺口，别把拆分做虚。

首次派发前把形态告诉用户。一个没打招呼就烧掉一天的研究 run，不会再被信任。

## 保住你自己的上下文

研究员在独立上下文里跑，是为了让你的上下文装*判断*而不是材料。这只有在你不是每阶段都重读一切时才成立。

- 卡返回时，完整读一遍交付物。**若节点有 5 张以上卡**，写一份**卡摘要**——150–250 字：它确立了什么、最强证据、声明的缺口、与其他卡相抵触之处——存为 `cards/<card>/summary.md`。5 卡以下跳过（此门限是经验值：单卡交付物很长时可以提前写摘要，很短时可再放宽）。
- 此后从摘要工作。只有审查异议、汇合或报告取决于某处细节时才回读全文。
- 结论与终稿从摘要加定点重读写成，不是从全语料。若你发现自己在第三次重读，说明摘要太薄——修摘要。

没有这条纪律，一个 30 节点的 run 会在节点预算耗尽前先耗尽上下文，而失败的样子看起来像写得差，不是窗口用完了。

## 用户改问题时

研究问题可以中途变。显式处理——不要悄悄绕着重新规划。

1. 把新表述**追加**到 `question.md` 的 `## Revised` 标题下并注明日期。绝不编辑原文：被问过什么的记录是审计的一部分。
2. **判定波及范围并说出去。** 三种情形：
   - *收窄或澄清*（同概念、更小范围）：计划照旧；在每个受影响的 `plan.md` 记录范围变化并重跑覆盖表。
   - *换框架*（同样措辞背后的另一个问题）：旧结论作为旧问题的发现保留；为新问题开新的根级线并携旧材料进入。仍与新框架相关的卡不要重新派发。
   - *换题目*：停止 run（`status: "abandoned"` 并写原因），开新的。保留旧 run 正是保住它的证据。
3. **记入 `run.json`**（`question_revisions: [{"at": "...", "what": "...", "effect": "carry|replan|abandon"}]`）。
4. **告诉用户代价**——哪些卡作废、哪些可复用。

最不能做的是：沿用旧 run 的结构回答新问题，却把它呈现得像按新问题研究过。

## 报告语言

终稿文章用提问时的语言写，除非用户另有说明。研究笔记、findings、审查用材料本身的语言——报告不行。

## 六道关卡

六个判断决定工作能否离开当前阶段。两个 critical：失败即停止交付。

| 关卡 | 等级 | 拦什么 |
|---|---|---|
| **Angle**（判断） | critical | 该下判断的地方交了一份来源综述 |
| **Citation**（引文） | critical | 不存在的著作，或没说过这话的著作 |
| **Coverage**（覆盖） | major | 建立在检索遗漏上的自信答案 |
| **Taxonomy**（分类） | major | 章节互相重叠或漏掉一块真实区域 |
| **Calibration**（校准） | major | 断言强于证据 |
| **Weaving**（织入） | major | 一段一来源的目录式行文 |

两条规则值得在这里写明，因为常有人与之争：

**Calibration**——断言强度绝不超过证据强度。多项独立研究才配"证实"；两三项只配"提示"；一项只配"可能"；什么都没找到就明说"未检索到"，而不是宣布为假。过度断言是显性失败；把扎实发现埋在一堆对冲词下是另一种。

**Citation**——每条引文带五态之一：`verified`、`partial`、`unverified`、`unreachable`、`invalid`。后两态绝不混淆：`unreachable` 是抓取失败、来源很可能真实；`invalid` 是注册机构拒绝或著作不存在。混同两者，要么冤枉正确的工作，要么放走一条编造的标识符。承重断言还需要两个独立来源，或显式的 `single_source: true`。

完整判据读 `references/10-gates.md`；阶段边界跑 `check.py --gates`，把关卡当清单看：它按
关卡分组报告，六门禁全 `clear` 才 `verdict: OK`（exit 0）；任一门禁或非门禁项的 P0 都让
它 exit 2。六门禁都会真失败——**Taxonomy** 查按来源/卡分节与章节重叠，**Weaving** 查一段
一来源的目录式行文，两者读终稿正文并点名是哪几节有问题（判据见 `references/10-gates.md`）。

## 一个完整走通的例子

仍是真实 run 的最小形态：一节点、两卡、一轮审查、不分叉。问题刻意很窄，因为要看的是形状不是题目。

```bash
SKILL_DIR="<本 skill 的路径>"
python3 "$SKILL_DIR/scripts/scaffold.py" ~/Documents/ordinance \
  --question "1918年大流感改变了日本的公共卫生立法吗？" \
  --depth 1 --cards 2 --followups 1 --revisions 1
# run r_a78c357a 创建于 ~/Documents/ordinance/research/r_a78c357a
# 根节点 n_d8acf9fa 位于 .../nodes/01-1918年大流感改变了日本的公共卫生立法吗
```

**阶段 1——计划。** 写 `nodes/01-.../plan.md`，带上校验器认的章节标题。
覆盖表是设计所在；空格就是声明的缺口：

```markdown
## 任务卡
| id | 任务 | 研究员 | 理由 |
|---|---|---|---|
| `c1-statutes` | 1918–1922 年立了什么法？关于流感说了什么？ | general-purpose | 读法令与官报 |
| `c2-administration` | 无法可依时，官僚系统做了什么？ | general-purpose | 读省厅通知与预算 |

## 覆盖
| 子问题 | 卡 | 缺口 |
|---|---|---|
| 法令文本 | `c1-statutes` | — |
| 省厅指导 | `c2-administration` | — |
| 府县执行 | — | **declared gap：无卡，经约定不在范围** |
```

```bash
python3 "$SKILL_DIR/scripts/check.py" ~/Documents/ordinance
# verdict: OK — 0 advisory note(s)      （节点还是 queued，目前查的还不多）
```

计划展示给用户。批准后把 run.json 中节点置为 `executing`，开始派发。
**阶段 2——卡。** 一条消息两个 `Agent` 调用，各带 `references/08-prompts.md` 的研究员模板加该卡任务。各返回交付物＋`findings.json`。
**阶段 3——结论。** 完整读两份交付物；写带反证、前提、局限与来源的 `synthesis.md`。节点置 `reviewing`。
**阶段 4–5——批判与处置。** 派审查员，带上结论*和你的推理*。它返回 `issues.json`。逐条处置实质问题；这里有一轮修订可用：

```json
{"id": "i1", "material": true, "disposition": "concede",
 "reason": "结论从三个府县概括全国；覆盖缺口属实，修订中把断言收窄到这三个府县。"}
```

**阶段 6–7——可能性与决策。** 同一审查员、新会话，返回 `possibility.json`。把提案誊入 `run.json` 的 `alternatives`、处置缺口，然后记录决策或写 `"no_forks": true`。

```bash
python3 "$SKILL_DIR/scripts/check.py" ~/Documents/ordinance
# verdict: OK — 0 advisory note(s)
```

run 现在是一个已关闭的节点。真实问题通常要分叉；例子停在一节点是为了看清形状。从这里起接手的是 `references/06-graph.md` 与 `references/07-report.md`。

## 失效模式，以及各自的内心体验

这是本流程实际出毛病的方式。认出症状，修复就完成了一半。

| 症状 | 实际发生的事 | 修法 |
|---|---|---|
| 结论流畅、有条理，引用的著作没人打开过 | 结论从研究员的摘要行写出，不是从他们的文件 | 完整读每份交付物；逐条把 `quote` 对回文件——机械部分 `check.py` 管 |
| 每轮审查都冒出十条新实质问题 | 审查员把风格偏好标成了实质 | 收紧审查员提示词里 `material` 的定义；实质问题必须能推翻、拆掉或实质掏空结论 |
| 审查两轮都一无所获 | 审查员只拿到了结论，没拿到推理 | 把裁量过程发过去；看不到推断的审查员攻击不了推断 |
| 卡派发两次失败、上游 502 | 网络/供应方故障，不是设计错误 | 见"故障、重试与降级"：重试 2 次→协调人执行→`card_note` 留痕→终稿披露 |
| 外部来源反复抓不到 | 抓取工具或网络不通 | 换 `curl -sS -A "Mozilla/5.0" --max-time 25` 重试；仍败标 `unreachable` 记尝试；连败 2 次列 declared gap |
| 六个节点全在说同一件事 | 为 paths.md 上已有的可能开了分叉 | 每次决策前读 `paths.md`；重复的标 `covered` |
| 结论每轮修订都悄悄变短 | 凭记忆重写而不是对着上一版写 | 读 `synthesis-N.md`，未触及的部分原样全文搬运 |
| 报告读起来像项目日志 | run 词汇漏进了正文 | 节点 id 进附录 I；正文按各线论证的内容命名 |
| 卡回来每张只有一段 | 一张卡捆了多个行为者、时段或维度 | 按单元拆卡；一卡一个研究员能扛到底的任务 |
| 用户被成本吓到 | 派发前没给估算 | 首次派发前说清形态（见"成本"节） |

## 提示

- **先写覆盖表再写卡。** 空格就是研究设计。一张没有空格的表，通常是一个没问过自己缺什么的计划。
- **每个阶段边界跑 `$SKILL_DIR/scripts/check.py --gates`。** 它按关卡而非按文件报告，正是你能动手的顺序。审查还热着时补一个缺失处置很便宜。
- **宁可让步，不要机智反驳。** 说出代价的结论强于驳倒每条异议的结论；被接受的代价清单正是读者信任的来源。
- **不要平均不相容的结论。** 两条线前提不同时，报告写明它们在哪里分手。一个谁都没论证过的中点，是一条带引文格式的编造。
- **事实出错记勘误，不要改历史。** 被纠正的结论保持原样；更正随行其侧，让记录显示什么变了、凭什么变。
- **正文里的数字和表格里的数字会漂移。** 每个数字只放一处并引用之，或交付前两处都查。
- **预算见底就停分叉，并说出去。** 未开的选项需要在 `paths.md` 记原因；"不值得"不算，"节点预算用尽"算。
