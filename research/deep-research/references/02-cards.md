# 阶段 2 —— 任务卡

一张卡是一个任务，由一个研究员在**独立上下文**里执行。你想从研究员那里要的一切都必须写进卡提示词：它看不到你的对话、你的计划、其他研究员的工作。

> 改动提醒：本文件的"研究员纪律"与 `08-prompts.md` 模板 1 是同一内容的两个视图——这里解释规则，08 是可直接粘贴的定稿。**修改任一处时必须同步另一处。**

## 研究员纪律

贴进每个研究员的提示词。这是每份交付物被评判的标准。

```text
[研究卡]

为完成本任务，按需阅读相关方法材料，以生成、比较或修订解释。

每条经验断言都要有可追溯的来源与逐字引文或精确位置；引用前先读已保存的材料。

事实、推断、诠释、规范性判断分开，并说明每条是哪一种。

随时记录反证、竞争解释与未决问题。实质性调查开始时，先找出能推翻工作前提的
证据或推理并刻意检验；前提变了就更新这个检验，而不是每次检索前重复仪式。

注意来源彼此是否独立：同一来源的三次转述只是一个来源。

权威、主流或反主流的意见、任务自身的前提，都不是证据。

材料拿不到时仍可带保留地结论：写明缺什么、它能定夺什么。

工作中随时申报发现（见下"Findings"）。更正先前申报的，注明 revises 哪一条。
```

其中四条值得讲明理由，因为研究员最爱跳过的就是它们：

- **独立性。** 引同一条通稿的三篇文章是一个来源、三个署名。把它们数作三个，是文献综述给自己注水的最常见方式。
- **任务自身的前提不是证据。** 卡上写"解释 1918 年大流行如何导致 1919 年立法"，研究员仍须能说出"某些法域里立法先于大流行第二波"。不会失败的卡不是研究。
- **先立证伪条件再检索。** 动手*前*说出什么能推翻工作答案，检索才不会变成寻找确认。
- **允许带保留结论。** 报告"省级档案无权限访问，因此关于执行的断言无支撑"的研究员，比悄悄丢掉这个问题的研究员有用。

## 交付物

卡的 `deliverable` 字段点名一个文件。研究员写它，外加 `findings.json`。

```text
nodes/01-.../cards/c3-prefectures/
├── provincial-implementation.md   # 计划点名的交付物
└── findings.json                  # typed、带定位的断言
```

交付物是写给读者的散文。它应当：

- 开头几段直接回答卡的问题，不是层层铺垫；
- 证据随行，带页码或章节引用；
- 写明没能确立什么、什么能定夺它；
- 不发明问题本身没有的结构。

## findings schema

`findings.json` 是机器可读记录。协调人的账本读它、审查员审它、`check.py` 校验它。

> 下例中的日期、引文、文件名都是**虚构**的，只为展示形状。不要抄进真实卡片；一个以假乱真的示例正是一条编造引文进入论文的方式。

```json
{
  "findings": [
    {
      "text": "1918 年内务省流感防疫令发布于 1918-10-25，早于第二波抵达东京。",
      "claim_type": "fact",
      "source_file": "sources/1918-kampo-1025.txt",
      "page": 3,
      "quote": "流行性感冒ニ関スル件ヲ定ム",
      "citation_state": "verified",
      "single_source": true
    },
    {
      "text": "时点提示该令回应的是第一波造成的行政紧张，而非第二波。",
      "claim_type": "inference",
      "source_file": "sources/1918-kampo-1025.txt",
      "page": 3,
      "quote": ""
    },
    {
      "text": "当时医师把该令读作既有惯例的法典化。",
      "claim_type": "interpretation",
      "source_file": "sources/ji-1919-p87.txt",
      "page": 87,
      "quote": "従来ノ慣行ヲ成文化セルモノ"
    }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `text` | 是 | 断言，一两句以内，完整命题 |
| `claim_type` | 是 | `fact` / `inference` / `interpretation` / `normative` 四选一 |
| `source_file` | **`fact` 必填** | 相对项目的路径，或 `doc:` 定位符 |
| `doc_id` ＋ `page` | 可代替 `source_file` | 12 位 hex 文档 id 与页码（从 1 起） |
| `quote` | **`fact` 必填** | 逐字原文，让读者能在页上找到 |
| `basis` | 无文件的非 `fact` 必填 | 一行写明断言靠什么：前提、立场或所诉诸的一般知识 |

没有定位符的 `fact` 是自相矛盾：指不到的东西，是穿着事实外衣的推断。`inference`、`interpretation`、`normative` **可以**没有文件——但必须用 `basis` 写明靠什么，`check.py` 查的是它的缺失而非文件的缺失。

绝不为过检查而编造 `doc_id` 或路径。`check.py` 校验路径存在、`quote` 在文件中；编造定位符是本流程唯一无法恢复的错误，因为下游一切都会把它当作已确认。

四种 claim_type 不是装饰，它们各背各的举证负担：

- **fact**——可对源查证。需要定位符，实践中还要引文。
- **inference**——由前提推出。写明哪些前提、什么会打断推理。
- **interpretation**——关于意义或论证力的论证。需要承认最强的对立读法。
- **normative**——价值判断。写明是谁的价值，且不得冒充事实。

标错类型是要盯的失效模式：把推断当事实陈述，是整个流程里最贵的错误，因为下游一切都会当作已确认。

字段语义要全卡一致：`single_source` 对"仅一份转录本、无正式出版物对应"的情形就应如实标 `true`，不要机械地一律 `false`——两种标法并存会让协调人与审查员都无法信任该字段。

## 可选字段

```json
{"text": "...", "claim_type": "inference", "source_file": "...", "page": 3,
 "depends_on": ["f-001", "f-004"], "uncertain": "该日期无第二来源",
 "revises": "f-002"}
```

- `depends_on`——本条依赖的发现，后续更正可向前追溯。
- `uncertain`——具体的未决问题，不是对冲话术。
- `revises`——被本条更正的早前发现 id。更正累积，不抹除。

## 协调人拿到卡之后

1. **完整读每份交付物。** 不是摘要行，也不只 `findings.json`。文件是证据；findings 是关于它的申报。
2. **把 findings 对回交付物。** 引文不在交付物里的发现，要么是错误，要么是研究员没给出工作过程的主张。
3. **找同一洞见出现两次。** 两个研究员从同一底层来源报告同一结论，是一个发现。合并之，并注明共享来源。
4. **记下没有任何卡覆盖的东西。** 那是后续轮要填的覆盖表行，或一个声明缺口。
5. **逐条检查 citation_state。** `verified` / `partial` / `unverified` / `unreachable` / `invalid`——未标注的发现读作未检查；`invalid` 的必须在下游引用它之前移除（见 `references/10-gates.md`）。

## 后续轮

首批卡返回后，可以把研究员再派出去——不超过 run 的 followup 限额。后续轮为**证据揭示出的缺口**而设，不是为计划时就看得见的广度。

后续计划里写明：

- 缺口是什么，一句话；
- 为什么新卡能填而首轮没填；
- 新卡可能修订哪些既有发现。

后续轮补完本节点的研究。它们不替代独立审查，也绝不用来审自己。

## 卡失败时

卡可能毫无有用产出，或研究员报告任务本身设计错了。两者都是正当结局，都必须记录：

- **重试**——任务对、执行败。重试一次，提示词中点名失败原因。
- **照样结论**——卡被访问权限或材料的沉默挡住。记录之，写明缺什么、它能定夺什么，继续走。带声明缺口的节点强于悄悄跳过一行的节点。
- **重规划**——任务错了。改计划，并把原因记入 `run.json`。

绝不为了让流水线走下去而编造一张卡的结果。审查员的第一项工作就是查事实，编造的交付物是本流程唯一无法恢复的失败。

> 派发层面的失败（子代理根本没跑起来、上游 502、超时、取消）按 `SKILL.md`"故障、重试与降级"处理：同卡重试至多 2 次，仍败由协调人亲自执行并留痕。

## 网络与抓取纪律（研究员适用）

- 内置抓取工具失败时换 `curl -sS -A "Mozilla/5.0" --max-time 25 "<URL>"` 重试 1 次；仍失败记 `citation_state: "unreachable"` 并写明尝试过什么。
- `unreachable` 不等于编造，也不是丢弃该来源的理由；如实记录。
- 同一来源连续 2 次抓取失败即列为缺口上报，不要无限重试。
- 检索文字材料时注意编校层陷阱：注释标记（如"赫鲁晓夫〔3〕那样的人物"里的〔3〕）、异体字、全半角差异都会让字面检索漏检——换关键词、去掉标记再试，并写明实际检索范围。

## 禁止

- 派卡时提示词里没有研究员纪律与交付物规格。
- 让研究员在完成自己的卡之前看到别的研究员的工作——独立线就是这样变成一条线的。
- 接受没有定位符的 `fact`。
- 把 `findings.json` 当交付物。它是交付物的索引，不是替代品。
- 悄悄丢掉失败的卡。记录它。
