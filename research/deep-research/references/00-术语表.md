# 术语表（中英对照）

本 skill 的文档以中文书写，但**机器校验的标识符一律保留英文**——`scripts/check.py` 与
`findings.json`、`run.json` 的读写双方都认这些字面值。翻译或改写任何文件时，以本表为准；
改术语必须先改这里，再全包同步。

## 角色与流程

| 英文 | 中文 | 说明 |
|---|---|---|
| coordinator | 协调人 | 主会话中的你：设计、判断、写结论，不亲自搜材料 |
| researcher | 研究员 | 子代理，一张任务卡一个独立上下文 |
| reviewer | 审查员 | 子代理，先批判结论、再（新会话）做可能性审查 |
| node | 节点 | 一次完整研究：问题＋计划＋卡＋结论＋审查＋分叉决策 |
| fork | 分叉 | 同一问题的真正不同答法，各成一个新节点 |
| join | 汇合 | 多条已完成的线合并向前走的新节点 |
| reconcile | 调和 | 一层节点全部关闭后的开节点/合并/记关系 |
| card / task card | 任务卡 | 研究员的一个独立任务 |
| deliverable | 交付物 | 卡产出的文件（不是聊天消息） |
| findings | 发现（findings.json） | 机器可读的带定位断言清单 |
| synthesis | 结论（synthesis.md） | 节点的答案，写出来是为了被攻击 |
| critique | 批判审查 | 审查员对结论事实与推理的攻击 |
| possibility review | 可能性审查 | 新会话中问"结论拒绝了什么、漏了什么" |
| disposition | 处置 | 对一条实质性异议的唯一记录归宿 |
| gap | 缺口 | 任何回答该问题者都必须补的东西，留在本节点内补 |
| possibility not taken | 另类可能 | 建立在别的前提上的路，进分叉决策 |
| ledger | 账本（run.json） | run 的唯一持久状态 |
| gate | 关卡 | 六个阶段放行判断（见下） |

## 六道关卡（名称保留英文，正文首次出现时附中文）

| 英文 | 中文 | 等级 |
|---|---|---|
| Angle | 判断 | critical（失败即阻断交付） |
| Citation | 引文 | critical |
| Coverage | 覆盖 | major |
| Taxonomy | 分类 | major |
| Calibration | 校准 | major |
| Weaving | 织入 | major |

## 冻结的机器字段与枚举（绝不翻译）

- `claim_type`：`fact` / `inference` / `interpretation` / `normative`
- `citation_state`：`verified` / `partial` / `unverified` / `unreachable` / `invalid`
- 处置七值：`revise` / `correct` / `rebut` / `concede` / `covered` / `park` / `branch`
- 缺口处置五值：`revise` / `rebut` / `concede` / `covered` / `park`（无 `branch`）
- 另类可能的 `outcome`：`option` / `declined` / `gap_revise` / `gap_rebut` / `gap_concede` / `gap_covered` / `gap_park`
- 节点状态：`queued` / `planning` / `awaiting_approval` / `executing` / `synthesizing` / `reviewing` / `disposing` / `possibility` / `filling_gaps` / `deciding` / `closed` / `skipped` / `failed`
- run 状态：`active` / `paused` / `done` / `abandoned`
- 节点 `kind`：`root` / `line` / `join` / `branch`
- 关系五值：`converge` / `diverge` / `resonates` / `appropriates` / `displaces`
- 布尔标记：`material`、`gap`、`own`、`no_forks`、`single_source`、`independent`
- 字段名：`source_file`、`doc_id`（12 位小写 hex）、`page`、`quote`、`basis`、`revises`、`depends_on`、`uncertain`、`covered_by`、`decided_at`、`stakes`、`premise`、`rationale`、`outcome_ref`、`question_revisions`
- 账本顶层集合：`nodes`、`decisions`、`joins`、`not_pursued`、`declined`、`relations`、`alternatives`、`errata`、`consent`、`limits`、`final`、`cost`、`question_revisions`
- 成本字段：`cost.tokens`、`cost.calls`、`cost.usd`、`cost.entries[].{at,node,tokens,calls,usd,what}`——由 `scripts/node.py spend` 写入，`status.py --cost` 读；改这些键名必须同步三个脚本
- `declined[]`（被拒绝的提案，`issue_id` 指向 alternatives id）与 `not_pursued[]`（不开的选项，记 `option`）是两件不同的事，别互相替用
- 文件名：`run.json`、`question.md`、`graph.md`、`paths.md`、`plan.md`、`synthesis-N.md`、`review-NN.md`、`possibility.json`、`findings.json`、`sources.md`、`final/`

## check.py 认的文档标题（中英均可）

- plan.md 必备：`Cards`/`任务卡`/`卡片`/`Assignments`；`Coverage`/`覆盖`；branch 节点还要 `Forks`/`Decisions`/`分叉`/`决策`
- synthesis 必备：`Sources`/`来源`（P0）；`Counterevidence`/`反证`/`反面证据`（P0）；`Premises`/`前提`/`预设`（P1）；`Limits`/`局限`/`不确定`/`未决`（P1）
