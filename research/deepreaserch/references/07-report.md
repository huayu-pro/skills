# 终稿报告

每个节点关闭后，run 交付一篇文章。四个阶段，第三个不可省略：被作者本人审过的初稿还是初稿。

| 阶段 | 谁 | 产出 |
|---|---|---|
| 1. **综述（survey）** | 你 | `final/<run>-survey.md`——每节点一节 |
| 2. **初稿（draft）** | 你 | `final/<run>-draft.md`——文章 |
| 3. **独立审查** | 一位**全新**审查员，未参与任何节点审查 | `final/<run>-review.md` |
| 4. **裁决（final）** | 你 | `final/<run>-final.md`——回应了审查的文章 |

每阶段完成即记入 `run.json`（`final: {"survey": "...", "draft": "...", "review": "...", "final": "..."}`）。阶段之间跑 `python3 "$SKILL_DIR/scripts/check.py" <project>`：它校验标 `done` 的 run 有 `*final*.md` **和**审查文件；**并且真的读交付文本正文**——每个形如项目路径的反引号定位符都要能解析到文件（也认 `final/sources/` 里的同名文件），指不到的会点名报 P1。**Taxonomy** 与 **Weaving** 两门禁也读终稿（无终稿时读初稿）：前者查按来源/卡命名的章节与标题重叠，后者查一段一来源的目录式行文，都点名是哪几节出问题。它读不了行文好坏——读行文的是审查。

## 阶段 1 —— 综述

每节点一节。每个节点写：

- 它的问题、以及怎么到达的——父节点、决策与选项、前提；
- 方法；
- 结论（最新版）与每轮修订改了什么；
- 关键证据；
- 审查员的反对与你对每条的处置；
- 针对它记的勘误；
- 可能性审查的提案与所做决策；
- 其子节点与携其向前的汇合发现了什么。

保留竞争性诠释与不确定性。**此处不裁决**——综述是地图，不是判决书。保留各节点的定义、前提与条件，使其与其他节点的差异保持可见。

写综述时会看见图上没记的关联——路径收拢、一节点与另一节点共振或替代。记为关系；它们随图进入终稿。

每节以点名节点的标题开始。

## 阶段 2 —— 初稿

禁止回答的约束解除。写文章。

### 这个阶段是什么

研究已经形成结论；本阶段把它们带到表达。从 run 的材料——各线结论、各自在批判下修订/驳回/让步了什么、决策、汇合、关系、勘误——里**抽出**论点、论证与关联，并对每条关联作出论证。

像学者判断一批证据那样判断：主张是否有支撑、发现彼此是否相关、立场能否调和。不要凭你的权威推翻或重称某线的结论；那需要证据，并按此处检索到的来源披露。

行文中把研究**确立**的与文章在综合时**推断**的分开。

### 材料与你已知的东西

- 材料可能载有你不知道的知识与远离通行观点的立场。**偏离共识不是错误**；不要把这类立场往主流"归正"。
- 在材料里也不等于为真。
- 你已有的知识用作**事实核查**——日期、数字、名字、归属、著作是否存在——不用作对诠释下判。
- 材料与你的知识在事实上冲突时，对源核验；定不了就**摆出冲突**，不要无声二选一。
- 支撑叙述的背景知识如此标注，且不引用 run 没读过的著作。

### 综合，不是目录

从发现彼此的关系里搭论证：一条线如何回答它出发时背离的结论、一次汇合如何与它的父节点对峙、各线在哪里收拢/分开/互替、共享哪些证据与前提。每条发现都应在论证里**干活**，而不是站在成绩单里。

前提不可调和时，保持立场分明并精确写出它们在何处、为何分开。不平均。不把不相容的主张并列呈现为同真。

### 形式

面向本学科读者、用提问语言写：

- **标题**、**摘要**、**关键词**；
- **引言**陈述问题、关键概念、以学术语言表述的研究设计与材料；
- **论证性的章节**——按问题与论证组织，不按研究怎么跑组织；
- **结论**；
- **成段散文**；列表与表格只用在比较需要处。

**正文不带 run 词汇。**不出现节点 id、卡名、轮次、"审查员"、"处置"、文件路径。研究线按它论证的内容命名；来源按作者与书名点名。读者不应看出这篇文章是一道流程组装的。

每条线的最终结论在论证中都有位置——作为发现、异议、限定或对立读法。没有一条因碍事被丢掉。

### 学术装置

可溯源性住在这里，不住在正文。

- **注释**给出作者、书名、年份、页或节。一手来源注明版本或档案。只在二手读过的地方按"转引自"标注。本地路径或 `doc:` 定位符可附于注内。
- **参考文献**：文章引用的每部著作。
- **附录 I——研究线**：每节点一行——平实的问题、一句话结论、正文何处接手、其 id。没有结论的线写明没有。
- **附录 II——记录**：答案接受的代价（concede 的异议）；勘误及其落实处；未走的路与理由；仍开放的（park 与未答的异议）；独立线收拢与分开之处。
- **附录 III——材料**：本 run 打开与下载过的一切，各一行。

### 判断

- 不表决；多数抹不掉少数观点。
- 分开经验主张、因果解释、诠释与规范前提。
- 各线分歧时，先查定义、范围、时段、方法的差异，**再**判分歧是否真实。只有证据能定时才解决它；否则保持开放。
- 给出植根研究的直接回答——各线前提不同时按各自前提条件化——连同最强的对立叙述、证据边界、未决问题、以及什么会改变答案。
- 分开**独立佐证**与对同一来源的反复依赖。
- **消解**：研究显示问题建立在混淆或意识形态前提上时，给出消解。若消解的是用户自己的问题，只有他们同意才算答案；没同意，就按原样回答问题、把消解作为读法之一附上并给依据。

### 写作中的检索

可以检索核实或比对已交证据所需的材料。保存进工作区、标明来源与路径，并在文中披露任何在此检索到的、改变某线结论的证据。不要把初稿变成不披露的新研究任务——大的未填需求标为局限。

## 阶段 3 —— 独立审查

一位**没有**审过任何节点的审查员。给它初稿、综述与来源访问权。任务书：

```text
像期刊评审一样审这篇初稿。检查：
- 事实、日期、数字、归属、被引著作是否存在；
- 初稿归于某来源的每条主张是否真在该来源中；
- 论证的承重推断是否成立；最强对立叙述是被回应了还是被漫画化了；
- 各线的发现被织入论证还是只是罗列；
- 不相容立场有没有被平均；
- 学术装置是否完整：每条文内引用进参考文献；附录条目齐全；
- 正文是否泄漏流程词汇。
每条反对写明什么能解决它。不要重写初稿。
```

## 阶段 4 —— 裁决

完整读初稿、审查、每条反对背后的来源。**批评不是判决**：对每条实质性反对接受、拒绝或保留分歧并说明理由。标准是对研究与证据的忠实，不是你对问题的先入之见。

- 缺来源、诠释冲突、规范分歧都不自动是事实错误。
- 不按表决或权威给观点排序。
- 接受更正后，复查受影响段落与结论；保留有独立支撑的内容。
- 加**附录 IV——审查**：哪些反对改变了答案、哪些被拒绝及为何、哪些仍悬而未决。
- 不隐瞒新证据，不把新主张冒充为初稿中已被审查过的。

终稿报告是终局审查。它不开新节点。

## 交付

- 全部通过 `check.py` 后，用 `python3 "$SKILL_DIR/scripts/export.py" <project> --run <run-id> --dest <交付目录> --name <名称>` 把终稿四件套与 sources/ 按你的命名习惯复制出去（也可手工复制 `final/` 下四个文件；缺 `sources/` 的引用是打不开的承诺）。
- 要别的格式：`--format html` 零依赖自研渲染（自含样式，可打印成 PDF）；`--format pdf` 或 `docx` 在本机有 pandoc 时由它转，没有则改出 HTML 并说明——不会静默降级。
- 要参考文献清单：`--references`（终稿有 `## 参考文献` 节就用该节，没有就从正文定位符抽出并提醒补节；条目在 `final/sources/` 里找不到对应文件会点名）。
- 要交付凭证：`--manifest` 产出 `<名称>-manifest.json`，逐项记字节数、sha256 与来源路径，并列出本次跳过了什么。
- 交付前把报告首段与末段对读：若两者对问题的回答不同——一处对冲一处断言、一处限于子案例一处概括全体——文章没写完。

## 禁止

- 把初稿当答案交付。
- 由写初稿的人审初稿——除非无子代理降级运行，此时在方法说明中标注 self-review（见 `SKILL.md`）。
- 正文出现流程词汇。
- 平均不可调和的立场。
- 因为某线结论让论证变复杂而丢掉它。
- 参考文献里出现没人打开过的著作。
- `check.py` 还有 P0 未清就交付。
