# 阶段 6–7 —— 可能性审查与分叉决策

批判循环问的是：*这个结论错了吗？*本阶段问另一个问题：**结论拒绝了什么、默认了什么、留下了什么没补？**

它在**全新会话**中、由同一审查员执行。刚花了三轮查事实的审查员已经变成了结论的编辑者；新会话恢复的正是局外人之眼。

> 改动提醒：本文件的核心提示词与 `08-prompts.md` 模板 3 是同一内容的两个视图。**修改任一处时必须同步另一处。**

## 审查产出两样东西

分开它们——混同是本阶段代价最大的错误：

| | 它是什么 | 去哪里 |
|---|---|---|
| **缺口（gap）** | 任何回答此问题的线都必须补的东西——一类来源、一个行为者、一个时段、一块结论忽略的证据 | **回到本节点**；在这里补，或在这里交代 |
| **未走的可能** | 建立在另一前提上的路，或把答案带向本线去不了之处 | 进**分叉决策**；可能成为新节点 |

可能性不能直接附到结论上：它假设了别的东西。缺口可以也必须在线内补。搞反了会产出两个典型失败——一张满是"其实没写完的作业"节点的图，和一篇塞满"别人应该研究什么"段落的结论。

## 可能性审查的核心

```text
## 目标
从 <path> 处为"<question>"所写结论做过的一连串选择来读它：每个选择都有所得、
有所失。把以下两样东西带到明处，并对每条提案说明它是哪一种：
- 它没有走的可能——主动放弃的与从未选过的：其他假设或解释、方法论、理论框架、
  意识形态与概念、视角、情景、读法、证据体及其携带谁的声音（其他来源、语言与
  行为者——受影响者与决策者皆是）、拆解问题的其他方式、以及对问题本身的批判。
- 它留下的缺口——忽略、不知道、没问，而任何回答此问题的线都必须补的东西。
  标 gap: true。
你不是在审这个结论的错；那已做过。

## 预设
结论——连同其背后的问题与计划——站在预设上：被当作给定的概念与范畴、分析单位、
时间范围与口径、它发言的立场、什么算证据、谁授权证据、价值前提、被接受的通行观点。
对每个承重的预设，指出结论在哪里用到它、靠它赚了什么、赔了什么、换来了什么。
不裁定它是否成立：那是研究。提出会去检验它的路径——查什么、若预设不成立答案会
变成什么——把选择权留给协调人。

## 什么构成一条提案
提案改变一个前提、方法、读法、视角或拆解方式，或点名一个缺口，并说明它能改变
答案的什么、需要什么研究。未走的可能要点名结论中它无法与之共存的东西。结论自己
的线容得下的——同前提下的另一工具、另一案例、另一批证据——不是可能：答案需要
它就是缺口，否则什么都不是。真实的每条都提，凑数的一条不提。

## 再往高处看一眼
当前答案的最高点能否上移？分别试想：换分析单位（从观念到制度、从文本到生产
文本的机制）、换对象（把被给定的统一对象拆成被制造的过程）、延长时间框架
（把终点后的余波纳入）。若某条换法能让结论回答一个更高层的问题，把它作为
可能提出来。
```

四条入手路径，在咬得住的地方用，绝不当标签贴：

- **关键词可能已经漂移。** 它在来源中、文献中、结论自己的用法里所指的可能不再是同一个东西。
- **什么算知识本身可能存疑。** 授权证据的那类记录、文体、学科，可以研究而非信任。
- **悬置理所当然的东西。** 先描述对象在来源中如何被构成，再假设它如名存在。
- **拆解继承来的概念。** 把它放回它为之形成的经验与问题，把框架呈现为必然之处读作情境与选择——谁的选择、封掉了什么。

## 先读路径表

提任何东西之前，审查员先读 `paths.md`：本 run 已提出过的每个可能、由哪个节点提出、归宿何在。

**表上已有的不再提。**若某节点已在追它——无论从哪个框架——或某个待开选项接了它，新提案在 `covered_by` 里点名那个节点。被拒绝或未开的路，只有拿出能回答当初拒绝理由的论证才可回来。

这条规则防止研究图变成镜厅：同一问题换四个名字在四层被研究，各得出同样的结论。

## 提案 schema

```json
{
  "alternatives": [
    {
      "id": "a1",
      "kind": "框架",
      "proposal": "把该立法读作殖民行政的工具而非国内公共卫生的工具。",
      "premise": "1918 年各项敕令出自同时管辖台湾与朝鲜的同一局；其范畴沿袭殖民卫生实践。",
      "rationale": "若框架成立，'国内能力'解释是帝国行政剧目的一种地方效应，比较对象从欧洲国家换成殖民当局。",
      "gap": false,
      "covered_by": ""
    },
    {
      "id": "a2",
      "kind": "缺口",
      "proposal": "没有任何卡查过敕令在北海道的执行。",
      "premise": "",
      "rationale": "结论从三个府县概括'日本'；北海道行政另成体系。主张全国效应的答案需要它。",
      "gap": true,
      "covered_by": ""
    }
  ]
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 处置与决策引用它 |
| `kind` | 建议 | 审查员自己的话；自由字符串 |
| `proposal` | 是 | 可能或缺口，写到能据此做计划 |
| `premise` | 可能必填 | 它假设或改变什么；结论中它无法与之共存的是什么 |
| `rationale` | 是 | 它能改变答案的什么、需要什么研究 |
| `gap` | 是 | `true`＝缺口（留在本节点）；`false`＝未走的可能（候选分叉） |
| `covered_by` | 可选 | 已在追它的节点，或接住它的待开选项 |

## 审查产出往哪去

审查员把 `possibility.json` 写进卡文件夹。**把每条提案誊入 `run.json` 的 `alternatives`** 再处置——决策的 `sources` 与缺口处置引用的是提案 `id`，而 `check.py` 读的是 `run.json`，不是卡文件。用 `outcome`（`option` / `declined` / `gap_revise` / …）或 `covered_by` 说明每条的归宿。

就记录而言，提案从未进 `run.json` 的可能性审查等于没发生。

## 处置缺口

缺口有自己的处置轮，选项更窄。**缺口绝不是分叉。**

| 处置 | 何时用 |
|---|---|
| `revise` | 本节点补它——**用一张卡**，前提是还有后续轮。轮次用尽则 `revise` 不可用：改选 `concede` 或 `park` |
| `rebut` | 它不是本问题的缺口 |
| `concede` | 结论没有它也成立并付出该代价 |
| `covered` | 另一节点拥有它；写明该节点如何回答 |
| `park` | 留待终审裁决 |

`branch` 不可用：发现其实是可能的缺口是被分错类了。重新分类，送去决策。

靠改写一段话"关掉"的缺口没有关掉。要么一张卡填它，要么结论明说没有它也成立（`concede`）或仍开放（`park`）。`--followups 0` 时 `revise` 不可用，**剩下 `concede`、`park`、`rebut`、`covered` 四种**——预期缺口可填的 run，计划时至少留一轮后续。

实战提示（来自真实 run）：缺口处置的三种常态是 `revise`（补一张追补卡，常以"gap-followup"命名）、`concede`（本地无此材料，如实挂起并写明后果）、`park`（需外部抓取、本轮不做，记为未决）——三种都是诚实结局，选哪种取决于材料可达性而非面子。

## 分叉决策

没有缺口可补之后，未走的可能进入决策。记录之前，把它们对着结论做过的选择读一遍——各赚了什么、赔了什么、换来了什么。

一个**决策**是带利害的问题加**至少两个互斥选项**，各带前提。本节点自己的线可以是一个选项。

```json
{
  "decisions": [
    {
      "id": "d1",
      "question": "1918 年立法是国内国家建构的工具，还是帝国行政的工具？",
      "stakes": "它决定比较对象，进而决定什么算这部立法的原因。",
      "options": [
        {"id": "o1", "label": "国内国家建构", "premise": "立法跟在战前国内行政能力之后。", "own": true, "sources": []},
        {"id": "o2", "label": "帝国剧目", "premise": "敕令移植殖民卫生范畴。", "own": false, "sources": ["a1"]}
      ]
    }
  ],
  "declined": [
    {"issue_id": "a3", "disposition": "decline", "reason": "该提案只是给既有线的方法换了个名字；答案不因此改变。", "covered_by": ""}
  ]
}
```

`declined` 是 run 级字段（与 `not_pursued` 并列，见 `references/09-ledger.md` 的顶层
schema）：`not_pursued` 记不开的**选项**，`declined` 记被拒绝的**提案**。`check.py` 校验它的
`reason` 点名了约束、且 `issue_id` 指向本 run 已知的提案。命令行记法：

```bash
python3 "$SKILL_DIR/scripts/node.py" <project> decline --option a3 \
        --reason "该提案只是给既有线的方法换了个名字；答案不因此改变。"
```

规则：

- **只有未走的可能才是分叉。** 缺口不是。
- **一个可能只开一次。** 路径表显示已有节点在追它，它就是被该节点 `covered`——不是新选项。
- **每条提案、每条 branch 处置的 issue 恰好记录一个归宿**——`option`（`outcome_ref` 点名选项）、`declined`、或某个 `gap_*` 态。必须唯一的是**归宿**而非提及：一条提案合法地同时为多个选项的 `sources` 供前提——两条线可以踩同一个可能。不要强迫二选一——那丢信息。
- **共同构成另一条路的提案合为一个选项。**
- **暴露了你这条线所依赖预设的提案，在答案取决于它时就是分叉。** 新节点研究该预设是否成立、不成立时答案变成什么。
- **针对问题本身的批判与其他可能同等。** 质疑通行观点的也是：观点通行是研究它的理由，不是拒绝它的理由。
- **记录每个真实分叉，不凑数。** `decisions: []` 在无分叉时是合法结局——明确写出来。
- **"不值得"不是拒绝的理由。** 真实的可能要么开出，要么把预算写成理由。

## 禁止

- 把缺口当分叉，或把分叉当缺口。
- 提出路径表上已有的可能而不点名覆盖它的节点。
- 因为不舒服、非主流、或矛头指向问题本身而拒绝提案。
- 还有后续轮时用散文填缺口。
- 在批判会话里跑可能性审查——必须是新会话。
- 此阶段无声翻掉一个 concede 或 rebut。
