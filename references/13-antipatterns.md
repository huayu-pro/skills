# 反模式：症状 → 诊断

> 用于「我知道它看起来不对，但说不出哪里不对」的时刻。按症状查表，不要按理论查。

## 整体印象类

| 症状 | 最可能的原因 | 规则 |
|---|---|---|
| 像后台原型 / 像线框图 | 层级没做（三档同权重）+ 背景纯白 + 组件是库默认样式 | §2.1 §8.2 §8.7 |
| 像模板 / 见过一千次 | 等分网格 + 居中英雄区 + 每区块淡入 + 通用 CTA 文案 | §3.5 §8.1 §9 |
| 廉价 / 不高级 | 边框 + 阴影 + 背景差三者同时用；阴影单层纯黑；颜色过多 | §6.2 §6.6 §5.4 |
| 吵 / 累 | 主色面积过大；三个以上实心按钮；每张卡片都有阴影和悬停动画 | §5.4 §2.7 §6.5 |
| 脏 | 中性色混用暖冷；渐变跨色相；彩色背景上叠灰字 | §5.3 §5.9 §2.3 |
| 平 / 没层次 | 全是同一表面色，没有深度差；字号档位太密 | §6.1 §6.3 §4.1 |
| 空 / 没内容感 | 留白过多但无结构；缺视觉锚点 | §8.1 §3.5 |

## 层级类

| 症状 | 原因 | 规则 |
|---|---|---|
| 不知道先看哪 | 内容未分级，或分级了但视觉上没差别 | §2.1 |
| 所有东西都在喊 | 用字号和字重同时强调所有元素 | §2.4 |
| 标题不突出 | 靠字号单打，没配字重和颜色；或标题本身不是最重要内容 | §2.2 |
| 次要信息太抢 | 次要内容用了主文字色 | §5.6 |
| 彩色背景上的文字发灰发脏 | 用了灰或半透明白 | §2.3 |
| 按钮不知道哪个是主 | 多个实心按钮 | §2.7 |

## 间距与布局类

| 症状 | 原因 | 规则 |
|---|---|---|
| 页面「乱」，但每块单看都还行 | 组间距 ≤ 组内间距 | §3.6 |
| 挤 | 留白不足（系统性低估） | §3.1 |
| 空旷但不知道为什么 | 留白有，但没有组结构，或容器宽度不一致 | §3.6 §3.7 |
| 排版像拼接 | 不同区块用了不同容器宽度 | §3.7 |
| 移动端横向滚动 | 固定宽度元素 + 不换行 flex | §3.8 |
| 卡片高度参差 | 内容长度不同但没用 `stretch` 或 `min-height` | §3.3 |
| 一行按钮高矮不一 | 按钮高度不在同一档位 | §3.3 |

## 排版类

| 症状 | 原因 | 规则 |
|---|---|---|
| 读起来累 | 行宽 > 75 字符，或行高 < 1.4 | §4.3 §4.4 |
| 文字挤在一起 | 行高用了固定 px 而不是相对值 | §4.4 |
| 标题松散 | 大字号没加负字距 | §4.5 |
| 字号之间分不清 | 字阶比值 < 1.2 | §4.1 |
| 字体不搭 | 两个同类型字体混用 | §4.2 |
| 数字列不齐 | 没用 `tabular-nums` | §4.8 |
| 中文看起来奇怪 | 行高按英文设的（1.5）；中西文之间无空隙 | §4.9 |

## 配色类

| 症状 | 原因 | 规则 |
|---|---|---|
| 颜色看起来脏 | 中性色不带色相 / 混用暖冷 / 色阶手挑 | §5.2 §5.3 |
| 深色模式刺眼 | 反色得到的 / 纯黑背景 / 纯白文字 | §5.5 |
| 强调无效 | 主色面积 > 10% | §5.4 |
| 配色不协调 | 色阶非算法生成，色相漂移 > 30° | §5.2 |
| 色带 / 断层 | 大面积渐变无噪点 | §5.9 |
| 对比度不够 | 未计算，或用了半透明/opacity 未算复合 | §5.7 |

## 深度类

| 症状 | 原因 | 规则 |
|---|---|---|
| 阴影像贴纸 | 单层、纯黑、`y = 0` | §6.1 §6.2 |
| 元素都浮着 | 所有卡片都加阴影 | §6.5 |
| 深度层级混乱 | 超过 5 档 | §6.3 |
| 深色模式下无层次 | 只靠阴影，没用表面亮度差 | §6.4 |
| 同时有边框和阴影 | 分组手段重复 | §6.6 |

## 交互与状态类

| 症状 | 原因 | 规则 |
|---|---|---|
| 点按钮没反馈 | 没定义 hover/active | §9 |
| 键盘用户迷路 | 无焦点环 / 焦点环被 `outline: none` 移除 | §10.4 |
| 空页面像坏了 | 空状态写了搜索失败文案 + 保留了禁用控件 | §8.4 |
| 加载时跳动 | 无固定 `aspect-ratio` 的占位 | §7.6 §8.5 |
| 移动端按钮点不中 | 目标 < 24px | §10.5 |
| 动画让人眩晕 | 无 `prefers-reduced-motion` | §9 |

## AI 生成 UI 的典型指纹

这些特征单独看都不算错，但同时出现三项以上，几乎可以确定是未经设计的默认输出：

1. 深色近黑背景 + 单一荧光绿/朱红强调色
2. 暖米色背景（接近 `#F4F1EA`）+ 高对比衬线标题 + 陶土色强调
3. 每个区块 `fade-in-up`，每张卡片 `hover: -translate-y-1`
4. 所有卡片同一圆角、同一阴影（`0 4px 6px rgba(0,0,0,.1)`）
5. 全大写 + 大字距的 eyebrow 标签出现在每个标题上方
6. 元数据用 `·` 连接（`A · B · C`）
7. 标签写成 `WORD — fragment`（带空格的破折号）
8. 链接和按钮文字后面都加 `→`
9. 小数据标签用等宽字体
10. `#0B0B0B` 这类「染色黑」冒充纯黑
11. 三档等分卡片，中间那个抬高 + 描边 + "Most popular"
12. 01 / 02 / 03 编号用在非序列内容上
13. 标题里单独一个词用斜体或异色强调
14. Lorem ipsum 或「示例文本」

**处理方式**：不是全部禁用，而是**要求它们是被选择的，而不是默认的**。如果简报明确要求这种风格，照做；如果简报没要求，不要在这里花掉自由度。
