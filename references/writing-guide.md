# 写作规范与反模式

第三步生成 SKILL.md 正文与配套文档时读本文件。SKILL.md 第三步保留两条硬规则（渐进式披露三级、「何时使用」信息全部放 description）；这里是展开的写作细则。

## 写作规范

- 祈使句为主，但解释 why——让模型理解原因比堆 MUST 有效；发现自己满篇 ALWAYS/NEVER 是黄灯信号，改写成讲道理。
- 可枚举事实用表格，命令用 bash 代码块，验收用 `- [ ]` 清单。
- 先写草稿，再以新鲜视角重读一遍再改一轮。

## 反模式

| 避免 | 应该 |
|---|---|
| description 总结工作流 | 只写触发条件——模型会按摘要行动而跳过正文 |
| 用 `<details>` 折叠省上下文 | 拆成 references/ 按需加载，折叠不省 token |
| 为个别示例特化、过拟合 | 从反馈归纳可泛化的行为 |
| 重复造轮子 | 先行研究已有高质量技能就推荐或改进它 |
