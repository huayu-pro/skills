# 审计规则与发现格式

> 用于 Workflow C（改进）与 Workflow D（评审）。`scripts/audit.py` 输出的确定性发现使用**同一套 schema**，可以和人眼发现合并排序。

## 七镜扫描（顺序固定）

顺序是因果的，不是随意的。层级问题会改变什么算间距问题，间距问题会改变什么算边框问题，收尾细节在结构坏掉时毫无意义。

```
1 层级 → 2 布局与间距 → 3 排版 → 4 配色 → 5 深度 → 6 图像 → 7 收尾
```

不要跳镜，不要按发现顺序排列输出。

## 严重度

| 级别 | 定义 | 判据 |
|---|---|---|
| **P0** | 可用性受损 | 层级崩塌、文字不可读、对比度不达 WCAG、无路可走（无主行动/无焦点）、内容溢出破坏布局 |
| **P1** | 一致性受损 | 非系统取值、组间距模糊、彩色背景上的灰字、行动未分级、缺状态设计、缺 `prefers-reduced-motion` |
| **P2** | 打磨缺失 | 深度未利用、组件是库默认样式、背景是纯白、缺焦点环设计、图标风格不一 |

P0 必须报告，即使用户只问了别的事。

## 发现 schema

每条发现必须包含这九个字段。缺任何一个都不算合格的发现：

```json
{
  "id": "H-001",
  "lens": "hierarchy",
  "severity": "P0",
  "location": "src/components/PricingCard.tsx:42",
  "rule": "§2.7",
  "now": "三个卡片都有实心主按钮，没有主次",
  "proposed": "只有 Growth 卡片用实心主色按钮，其余用 outline",
  "effort": "S",
  "evidence": "screenshot:1280 或 code 或 measured",
  "verified": true
}
```

- `lens`：`hierarchy` / `spacing` / `typography` / `color` / `depth` / `imagery` / `finishing` / `motion` / `a11y` / `copy`
- `rule`：可追溯到 `references/` 的规则编号，或 `a11y:contrast` 这类确定性检查名
- `evidence`：`screenshot:<width>` / `measured:<what>` / `code` / `heuristic`
- `verified`：`true` 表示看过渲染结果；`false` 表示只读了代码（必须在报告中标注）

## 七镜检查清单

### 镜 1 · 层级

- 每屏最突出的元素是不是最重要的内容？
- 次要内容在不读文字的情况下能否被识别为次要？
- 主行动是否唯一？旁边有无同权重竞争者？
- 正文颜色是否 ≤ 3 档？字重是否只用两档？
- 彩色/深色背景上的次要文字，是否同色相降明度（而不是灰）？
- 语义标签与视觉层级是否分离（`h1` 不因字号被降级为 div）？

### 镜 2 · 布局与间距

- 组间间距是否 ≥ 组内间距的 1.5 倍？（用脚本量，不靠感觉）
- 所有间距值是否在刻度内（4 的倍数，相邻比值 ≥ 1.25）？
- 同一行的按钮高度是否一致？
- 有没有为了分组而加的边框，其实是留白能解决的？
- 六个宽度（320/375/768/1024/1280/1440）下有无横向溢出？
- 网格是否全是等分（等分通常意味着没做内容分级）？

### 镜 3 · 排版

- 字阶是否由比值生成？相邻档比值 ≥ 1.2？
- 正文行宽是否 45–75 字符？（量 `max-width` 与 `font-size`）
- 行高是否随行长/字号变化？正文 ≥ 1.4，大标题 ≤ 1.2？
- 字体是否 ≤ 2 个且角色不同？
- 三行以上文本有没有被居中？
- 数字列是否 `tabular-nums`？
- 有没有 300 字重做正文？

### 镜 4 · 配色

- 色阶是否算法生成，色相旋转 ≤ 30°？
- 中性色是否带统一色相（不是纯灰）？
- 主色占页面面积是否 < 10%？
- 正文颜色是否 ≤ 3 档？
- 所有文字/背景对是否算过对比度？半透明的是否算了复合值？
- 深色模式是否重新设计表面层次（不是反色）？
- 渐变两端色相是否接近？

### 镜 5 · 深度

- 所有阴影 `y > 0`？
- 阴影是否 ≥ 2 层？
- 阴影颜色是否带色相？
- 层级是否 ≤ 5 档？
- 有没有元素同时用边框 + 阴影 + 背景差？
- 深色模式是否用表面亮度差而不是只靠阴影？

### 镜 6 · 图像

- 每张图的裁切策略是否明确（`aspect-ratio` + `object-position`）？
- 文字叠图是否有遮罩，且验证了最亮区域对比度？
- 图标是否同一套、同笔画、同尺寸档位？
- 图像是否有占位/失败/空三态？
- 是否用 `object-fit: fill`（会变形）？

### 镜 7 · 收尾

- 页面上有几个「记得住的东西」？（应 ≤ 1）
- 背景是否纯白？
- 边框颜色是否都在 10% 透明度以内？
- 空状态是否隐藏无意义控件并给出主行动？
- 加载/错误状态是否设计过？
- 焦点环是否自定义？
- 组件是否只是库默认样式？
- 非用户触发动效是否 ≤ 1？
- 注意瞬间是否有起点/终点两帧或 3 秒录屏？只有静态首屏 → `skipped: no motion evidence`。
- 390 微尺度五项：数字与地名/标签不碰撞、端点标签不越界、无孤立单字、
  触控目标 ≥44×44、最后一行不是压扁的桌面版。

### 附加镜 · 无障碍与文案

不属于七镜顺序，但每次都跑：

- 键盘能否走完全流程？焦点环可见？
- 每个输入有 label？错误有 `aria-describedby`？
- 触控目标 ≥ 24px（推荐 44px）？
- 模态有标题、困住焦点、`Esc` 可关？
- 文案是否说清结果？错误含原因和下一步？首次使用与搜索无结果是否区分？

## 确定性检查（`scripts/audit.py`）

脚本做机器能确定判断的部分，输出同一 schema。覆盖：

| 检查 | 级别 | 说明 |
|---|---|---|
| 硬编码颜色 | P1 | `#hex`、`rgb()` 直接写在组件里而非 token |
| `space-x-*` / `space-y-*` | P1 | 应改 `gap-*` |
| 非系统间距 | P1 | Tailwind 里的 `p-[13px]` 之类任意值 |
| 缺 `alt` | P0 | `<img>` 无 `alt` |
| 缺 label | P0 | `<input>` 无关联 label |
| 对比度不足 | P0 | 解析出的文字/背景对 < 4.5:1 |
| `outline: none` 无替代 | P0 | 焦点不可见 |
| 无 `prefers-reduced-motion` | P1 | 有 animation/transition 但无该媒体查询 |
| 居中文本 | P1 | 启发式：单个居中文本节点 > 120 字符（≈2 行）；`text-align:center` 设在 body/html 上并有多段落 → P0 |
| 纯黑/纯白背景 | P2 | `#000`、`#fff` 作为页面背景 |
| 单层阴影 | P2 | `box-shadow` 只有一个值 |
| 图标尺寸硬编码 | P2 | 组件内 `w-4 h-4` — **脚本未实现，需人工看** |
| Lorem ipsum | P1 | 占位内容 |

**"未检查"必须显式输出**：如果某个检查因为无法解析而跳过，报告里写 `skipped: <reason>`，不要静默当作通过。

```markdown
**镜次**：七镜 + a11y + copy

## P0

|---|---|---|---|---|---|---|

## P1

## P2

（脚本输出摘要 + skipped 项）

## 未验证的发现
（evidence=code 的条目单独列出）
```

## 修复顺序

**结构先于外观**。加留白经常让「要不要边框」这个问题消失。所以：

1. 层级（P0）
2. 间距与布局（P0/P1）
3. 排版（P1）
4. 配色（P1）
5. 深度（P2）
6. 图像（P2）
7. 收尾（P2）

每一处修改引用规则编号，作为可审查的 diff 提交。
