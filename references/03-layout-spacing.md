# 布局与间距

> 教材第 3 章。规则编号 `§3.x` 对应 *Refactoring UI* 原书章节。

## §3.1 从过多的留白开始，再往回减

留白不足是新手最常见的问题，而且**人眼在编写过程中会系统性地低估所需留白**。原因很朴素：你在编辑器里看到的是一行行代码，不是最终比例。

所以工作流是：先给到你觉得「有点过分」的留白，截图，然后往回减。反向操作（从紧开始加）几乎必然停在不足的位置。

具体量级参考（1280 宽）：

| 位置 | 起步值 | 常见最终值 |
|---|---|---|
| 区块之间（section padding-block） | 128px | 80–112px |
| 卡片内边距 | 32px | 24–32px |
| 表单字段之间 | 24px | 16–24px |
| 段落之间 | 1.5em | 1em–1.5em |
| 标题与正文之间 | 24px | 16–24px |

这些是**起点**，不是答案。判断依据永远是截图，不是数值本身。

## §3.2 一切尺寸来自系统

间距、字号、圆角、边框宽度、阴影模糊半径，全部从一套预先定义的刻度里取。禁止「这里差一点，写个 13px 吧」。

**间距刻度**（4px 基准，与 Tailwind 默认一致）：

```
4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96 · 128
```

规则：**相邻两档的比值不小于 1.25**。若需要 13px，说明 12 或 16 都行，选一个。

**为什么禁止手调**：手调的值会累积。一个页面出现 13/17/22/26 之后，下一个人会写 19/23，三个月后没人知道哪些是刻意的。

## §3.3 尺寸刻度不必和间距刻度相同

元素尺寸（图标 16/20/24，头像 32/40/48，按钮高度 32/36/40/44）可以有自己的刻度，但同样必须是**有限集合**。

按钮高度尤其重要：同一层级的按钮高度必须一致。一行里出现 38px 和 42px 两个按钮，读者说不出哪里不对，但会觉得粗糙。

## §3.4 不要靠边框解决分组

「这两块内容分不开，加条线吧」是错误的第一反应。边框增加噪声，而且一旦加了，往往还要加更多来平衡。

按顺序尝试：

1. **加留白**——组间距拉开，90% 的情况就够了。
2. **加背景色差**——极浅的表面色（比背景亮 2–4%）能分组而不加线。
3. **加阴影**——只在元素确实「浮起」时用。
4. **加边框**——最后手段，且用极浅的颜色（不是 `#ccc`，是 `#eaeaea` 或带透明度的当前文字色 8%）。

## §3.5 网格：先做不对称

等分网格（三等分、四等分）是最省事也最平庸的选择。真实内容几乎从不适合等分。

先问：这些内容里，哪一个是主角？然后给它更大比例：

```
✗  |----|----|----|
✓  |------|--|--|         主角 + 两个配角
✓  |--------|------|       2:1
```

侧栏布局同理：`280px + 1fr` 比 `1fr + 1fr` 更像产品界面。

## §3.6 组间距必须大于组内间距

**这一条能修掉大部分「为什么看起来乱」的问题。**

一组卡片里的卡片间距，必须明显小于这组卡片与下一组内容之间的间距。否则读者的眼睛无法判断边界在哪。

```
✗  [卡片] 24px [卡片] 24px [卡片]        ← 组内
         24px                              ← 组间，相等 → 全糊在一起
   [下一组标题]

✓  [卡片] 16px [卡片] 16px [卡片]        ← 组内紧
         48px                              ← 组间松
   [下一组标题]
```

比例经验值：**组间至少是组内的 1.5–2 倍**。达不到就说明分组是假的。

## §3.7 不要用容器宽度做视觉分组

「这个区块内容少，容器窄一点」——宽度变化会打断垂直节奏，让页面看起来像拼接的。

正确做法：容器宽度保持一致，用留白和背景区分区块。例外：正文阅读区（见 §4.3 的行长），它确实需要比全宽窄，但那是排版需求，不是分组手段。

## §3.8 响应式：先定断点行为，再定断点数值

不要问「断点设在多少」，要问「这个布局在什么宽度下会坏」。会坏的那一刻就是断点。

常见的坏点：

- 三列卡片在 < 768px 时单卡宽度 < 280px → 换两列
- 导航项在 < 900px 时挤压 → 折叠
- 表格在 < 720px 时横向溢出 → 换堆叠卡片（不要用横向滚动表格做主内容）
- 正文行宽超过 75 字符 → 收窄容器

**必须验证**：在 320 / 375 / 768 / 1024 / 1280 / 1440 六个宽度截图，检查 `document.documentElement.scrollWidth === window.innerWidth`。横向溢出是最常见的移动端缺陷，且肉眼在小截图里极易漏看。

## §3.9 空状态是布局的一部分

空状态不是「没内容时的占位」，它是这个功能在零数据时的**完整设计**。要点：

- 一句话说明这是什么（不是「暂无数据」）
- 一个明确的主行动（不是禁用按钮）
- 不要显示此时无意义的控件（筛选器、搜索框、空表格表头）

详见 `08-finishing.md` §8.4。

## 快速自检

1. 组间间距是否明显大于组内间距？（量一下，不要感觉）
2. 页面里出现的所有间距值，是否都在刻度表内？
3. 同一行的按钮高度是否一致？
4. 有没有为了分组而加的边框，其实是留白能解决的？
5. 六个宽度下有没有横向溢出？
