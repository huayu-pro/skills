# 阶段 4–5 —— 批判与处置

审查员攻击结论；你回答每条实质问题。然后要么结论修订、再审，要么循环关闭。

这是让本流程配得上其成本的阶段。没人攻击过的结论是一份带参考文献的初稿。

> 改动提醒：本文件的核心提示词与 `08-prompts.md` 模板 2 是同一内容的两个视图——这里解释规则与理由，08 是可直接粘贴的定稿。**修改任一处时必须同步另一处。**

## 审查员拿到什么

只看结论的审查员能查事实，却找不到你没写下来的承重推断。给它：

- 受审的结论；
- 本节点**每一轮计划**，从旧到新；
- 研究图（有哪些节点、各追什么、各结论在哪）；
- 结论引用的卡交付物——以及每张卡实际查过的材料；
- **你的推理**：结论背后的工作笔记与裁量过程，不只是结果。这是最有价值也最常被扣下的输入。
- 复审时：上一版与你对早前问题的处置。

## 批判提示词的核心

```text
## 目标
红队审查 <path> 处为"<question>"所写的结论。专找推理失败；
不扩写报告、不润色行文。把问题记入 issues.json。

## 检查什么
- 检验承载关键结论的前提，以及最强的竞争解释。
- 分清局部修补与推翻结论的缺陷。
- 事实与引文：日期、数字、事件、归属、被引著作是否存在。
  用你自己找的来源核对——先核那些什么材料都没查过的卡里的断言。
  读两遍不等于核过一遍。核出事实错误即是实质问题：写明你拿什么对的。
- 推断与因果；概念与范围；方法与抽样；立场与偏差；被省略的行为者与过程；
  互动；时间范围；后果；以及伪装成事实的规范性判断。
- 计数复核：凡"出现 N 次/共 N 处/字数 N"类断言，按结论写明的计数规则重算一遍；
  没写规则的，实测后指出计数不可复现。
- 转引链：结论当作独立佐证并列的两条来源，若实际同出一源（同一转引的两次转述），
  点名并把"独立来源数"降下来。
- 内部一致性：关键证据表与反证表、正文与 Revisions 节，不得互相矛盾；
  一条证据不能在正面引用时算数、在反证节里又被排除。
- 检索范围：凡"零命中/未出现"式断言，检查结论是否声明了检索范围；
  词没出现推不出范畴不来自该文献。
- 缺口：结论忽略、不知道、没问，而任何回答此问题的线都必须补的东西。
  图中另一节点已拥有的问题不是本节点的缺口——点名那个节点。
- 结论是否回答了它的父节点、以及它被开出时所对立选项的最强版本，
  而不是只为自己前提辩护。
- 结论与裁量过程没说的：计划没走的方向、裁量绕开的问题——沉默承重之处。

## 复审（如有）
与上一版比较，包括没被任何问题触及的部分。检查每处修订是否解决了它要解决的、
每个反驳是否成立、修订本身引入或丢掉了什么。已被 concede、covered、park 的不再提，
除非本版改动了它。你仍不接受的驳回再次提出，并说明为何那个回答不成立。

## 验收
- 审查文件存在，且每条批评都说明其分量，以及解决它所需的证据、更正或具体核查。
- issues.json 载完整清单；一条没有就明确写 []。
```

审查员最容易做错的两条：

- **错误的反对与错误的主张同样有害。** 不同框架可以产出不同诠释而双方都不自动为错。把前提差异误判成错误的反对，浪费一次修订。
- **为批判父节点框架而开的节点，不背"回答父节点问题"的义务。** 对这种节点，检查它是否说清了问题在其批判下*变成*什么——消解、重构、收窄——以及凭什么。"它没回答原问题"对它不构成反对。

## issue schema

```json
{
  "issues": [
    {
      "id": "i1",
      "kind": "因果推断",
      "question": "该令的十月日期真的早于东京的第二波吗？",
      "rationale": "结论把第二波定为'1918 年秋'而无月份。若东京峰值在十月下旬，先后颠倒，推断失效。",
      "priority": 3,
      "material": true
    },
    {
      "id": "i2",
      "kind": "样式",
      "question": "'epidemic' 该大写吗？",
      "rationale": "仅表述问题。",
      "priority": 0,
      "material": false
    }
  ]
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 本轮内稳定；处置引用它 |
| `kind` | 建议 | 什么类型的问题，审查员自己的话——自由字符串，别把罕见的反对硬塞进错误类目 |
| `question` | 是 | 以问句形式陈述的反对 |
| `rationale` | 是 | 为何要紧、什么能解决它 |
| `priority` | 可选 | 整数，越高越急 |
| `material` | 是 | **只有实质问题需要你处置** |

`material: true` 意为：若它成立，结论就是错的、无支撑的或实质不完整。把 `material` 标对——全标实质，循环变成跑步机；全标非实质，审查形同虚设。

## 七种处置

每条实质问题恰好一个。记在 `run.json` 该节点的 `issues` 列表。

| 处置 | 何时用 | 必填 | 效果 |
|---|---|---|---|
| `revise` | 结论必须改。缺口形状的反对在还有后续轮时需要**一张卡**；论证形状的反对可以改写。轮次用尽时仍允许改写——论证问题与缺口不同，散文答得了 | `reason`、`revision` | 新的 `synthesis-N.md`；审查员再审 |
| `correct` | 修订已用尽，且问题点名一个明白错误（错的数字、日期、名字、文献、或修订本应删掉的句子） | `reason`＝更正后的文本 | 作为更正附在结论后；不再审 |
| `rebut` | 反对不成立 | `reason`＝给审查员看的答复 | 审查员可以拒绝该反驳并再次提出 |
| `concede` | 立场保留并付出此代价 | `reason`＝接受的代价 | 列入终稿"答案接受的代价" |
| `covered` | 本 run 另一节点拥有此问题 | `covered_by`、`reason`＝该节点如何回答它 | 此处不研究 |
| `park` | 留待终审裁决 | `reason`＝为何留开 | 列入未决问题 |
| `branch` | 它揭示的是真正的另类可能而非错误 | `reason`＝那个可能 | 可能性审查之后进入本节点的决策 |

维持循环诚实的规则：

- **更正是 `revise`，绝不是 `branch`。** 明白的错误不是另一种读法。
- **原则性分歧是 `rebut` 或 `concede`，绝不是 `revise`。** 为平息反对而修订，是结论失去论证的方式。
- **只有发生修订时循环才再来。** 没有修订，审查即关闭。
- **修订预算用尽后 `revise` 不再可用。** 剩下的问题转 `correct`（明白错误）、`rebut`、`concede`、`covered` 或 `park`，并记录结论为何带着它出场。把最后一轮修订花在外观修改上的 run，是把它留给真正问题需要的预算浪费了——最后一场修订留给实质反对。
- **只有修订用尽才可用 `correct`。** 否则修复属于修订稿。
- **什么都不移交给从本节点开出的节点。** 本节点没填的，它 concede 或 park，记录在案。
- **`covered` 不等于解决了。** 拥有不是回答：写明那个节点的工作如何回答它，或什么仍开放。

## 决定前先问研究员

关于某张卡所交材料的异议，处置前可以打回给研究员。**重新派发那张卡的研究员**——多数 harness 无法续接已结束的子代理会话，所以派一个新的，带原交付物、争议中的发现、和问题。要简短回答，不要新交付物：

```text
你为任务"<卡的问题>"写过 <交付物路径>。
审查员提出此反对：<异议原文>。
只回答这一点：反对是否成立，你的材料中什么能定夺它？
若成立，直说，并给出正确的主张。
```

这常比只凭交付物裁断更快更准——研究员知道自己当时是什么意思。把答复记入该 issue 的 `reason`。

不要用它卸掉判断。处置权在你。

## 记录

```json
{
  "id": "i1",
  "material": true,
  "disposition": "rebut",
  "reason": "据府县死亡序列（卡 c3 表 2），东京峰值为 1918-10-18；全国峰值在 11 月不定东京的。该令早于东京峰值一周。"
}
```

反驳必须可查。"审查员错了"不是处置，是拒绝处置。

## 禁止

- 改了正文却不记处置。
- 为让一条你认定错误的反对闭嘴而修订——那该 rebut。
- `concede` 不写代价。
- `covered` 点名一个并不拥有该问题的节点。
- 一条 issue 处置两次，或留一条未处置。
- 只给结论不给推理，然后抱怨审查浅。
