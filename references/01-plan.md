# 阶段 1 —— 计划

计划是一份**研究设计**，不是一个答案。此阶段不解决问题，也不让教科书、主流观点或反主流观点冒充证据。

> 改动提醒：本文件与 `08-prompts.md` 的研究员提示词存在有意分工——这里讲规则与理由，08 是可直接粘贴的定稿。**修改任一处时必须同步另一处。**

## 设计必须确立什么

写第一张卡之前先想清这些：

1. **问题实际在问什么**——以及它还可能问什么。"X 的影响"可能在问因果机制、时人如何理解 X、X 使什么成为可能、或 X 的史学史。这些需要不同的卡。
2. **哪些前提未经检验。** 列出来。承重且可研究的前提属于研究范围——不能默认。
3. **在场的对象、过程、互动、时段与学科。** 留在约定的问题之内，并在其内完全分解。
4. **每张卡的证据需求、交付物、依赖与验收标准。**
5. **方法、理论与来源策略**——连同它们的盲区、以及与之竞争的方案之名。研究员选择并细化具体实现；计划说明这个选择押上了什么。

不要把问题硬塞进单一学科模板（PICO 框架、因果变量模型、从别处借来的分期）。不合身的模板产出的是回答模板的卡。

## 卡的粒度

一张卡是**一个研究员在一个会话里能扛到底的一个任务**。

- 问题取决于多个行为者、地区、机构、时段或维度的表现时，**各得一卡**，而不是共摊一卡。捆了多个单元的卡回来必浅——这是最常见的规划失败。
- **依赖**让一张卡等另一张的产出。只在真需要对方结果作输入时才给。依赖链会把并行工作无谓地串行化。
- **共享的定义、标准或基线**写进 `plan.md`，让所有卡从同一地基出发，而不是各自重新推导。
- **卡数跟着问题结构走**——不跟研究员人数（一人可持多卡、各在独立会话），也不跟并行限额（它只决定派发节奏）。
- 首份计划是**本节点整条线的设计**。后续轮次留给证据揭示出的缺口，不是留给现在就看得见的广度。

## 覆盖表

`plan.md` **必须**包含一张覆盖表：每个子问题、问题点名的每个行为者或维度，对照服务它的卡。

```markdown
## 覆盖

| 子问题 / 行为者 / 维度 | 卡 | 缺口 |
|---|---|---|
| 1918–19 年立法文本 | `c1-statutes` | — |
| 内务省内部指导 | `c2-archives` | 档案访问未确认 |
| 府县执行 | `c3-prefectures` | — |
| 当時医界意见 | `c4-journals` | — |
| 英文史学文献 | — | **declared gap：无卡，经约定不在范围** |
```

**空格是声明的缺口**，不是疏忽。某行没有卡，就在缺口列写明原因。这张表让审查员之后能问"你说过要覆盖府县执行——它在哪"，并得到回答而不是意外。

检索辅助（某领域的维度图、按分面计数的文献扫描）在这里有用，但计数是**发现信号**，不是相关性或完整性的证明——跨语言、跨来源类型、跨学派时尤其如此。

## 分叉：本设计已见的决策

问题容许真正不同答法时，把分叉**记进设计**，而不是假装一条路就是问题本身。

一个分叉是：

- 一个带**利害**的问题（答案如何随路径改变），加
- **至少两个选项**，各陈其**前提**——那条路假设或改变了什么。

```json
{
  "id": "d1",
  "decided_at": "n_d8acf9fa",
  "question": "1918 年的应对表达的是谁的能动性？",
  "stakes": "答案是关于国家能力还是关于市民组织，改变下游每一张卡。",
  "options": [
    {"id": "o1", "label": "国家能力读法", "own": true,
     "premise": "立法出自 1918 年之前建成的中央行政能力。",
     "node": "n_d8acf9fa"},
    {"id": "o2", "label": "市民组织读法", "own": false,
     "premise": "立法是对地方既有自发安排的追认。",
     "node": null, "reason": "", "covered_by": ""}
  ]
}
```

id 与 `decided_at` 必填：`run.json` 引用它们，`check.py` 校验每个选项 id 全 run 唯一、`decided_at` 指向真实节点。选项开出后填 `node`；不开就填 `reason`。

规则：

- **本节点自己的线可以是一个选项**（`own: true`）。其余每个选项是一个新的可能，在本层调和时开成节点。
- **记录每个真实分叉，不为了凑数编造。**
- **互补工作不是分叉。** 共同服务一个答案的部分是本计划的卡；共同构成*另一条*路的部分合为单一选项。
- **纠错与缺口绝不是分叉。** 后续轮次与修订在本节点内处理它们。
- **分叉可以是整个节点。** 只有决策没有卡的计划是纯分叉点：其选项同时、并行、独立地开出。几条线要三角互证（互相竞争的框架或读法，其*一致*应算独立证据）时，这正是正确形状。把你视为主线的线也放进去当一个选项；豁免它就毁掉了独立性。
- **追另一框架的节点必须检验该框架。** 在 `plan.md` 写明：这个框架引导你读哪些父节点线没读过的材料、其下什么算反对父节点结论的证据——并给那些材料配卡。把父节点的证据换个名字重新编码不是对框架的检验。

## 选研究员与审查员

按匹配度选每张卡的研究员，并用一行说明理由（`assignee_reason`）。"最合适"不是理由；"读得懂日文行政史料、做过明治时期公共卫生"才是。

**审查员**在计划时选定，身兼两职：本节点每版结论的批判，与——新会话中的——可能性审查。在 `plan.md` 写明该审查员的画像为何*同时*胜任两职。

## `plan.md` 必须包含什么

`check.py` 校验下列标题在场、且无占位符残留；它不判行文。骨架用 `assets/templates/plan.md`。

| 章节 | 校验器为何要它 |
|---|---|
| 点名任务卡的标题（Cards / 任务卡 / 卡片 / Assignments） | 没有任务的计划不是设计 |
| 点名覆盖表的标题（Coverage / 覆盖） | 空格是设计的声明缺口 |
| 点名分叉的标题（Forks / Decisions / 分叉），**纯分叉点必带** | 没记录分叉的分叉节点什么也没开 |

每张卡在表中还要有稳定 id：`run.json` 把卡文件夹记在 `nodes[].cards` 下，`check.py` 校验每个记录的文件夹存在。

每张卡写清：问题、交付物文件名及其必含内容、研究员人选与理由，以及——有用处时——方法、来源策略、证伪条件。卡的栏目是散文不是 schema；被*机器校验*的是文件夹与其中的 findings（见 `references/09-ledger.md` 与 `references/02-cards.md`）。

`deliverable` 值得斟酌——它是研究员被问责的验收标准：

```text
`naval-balance.md`
一张 1918–1922 年各强国主力舰吨位表，每行注来源；
随后 400–600 字：这张表没能定夺什么。
```

第一行只有文件名（可带反引号）。其后全是要求。含糊的交付物必须在派发前修好——说不清要产出什么的研究员会产出别的东西。

## 一条消息装不下的计划

分几次编辑写完 `plan.md`，或把后续轮拆成 `plan.md` 加 `plan-<round>.md`。不要为了一次写完压缩设计：要砍范围就跟用户砍，并把砍掉的部分作为声明缺口记入覆盖表。

## 审批与用户运行时约束

计划获批不只是"开始"的信号。用户在批准时给出的**运行时约束**（子代理数量上限、外部站点不可达时要报告、成本上限、交付目录与命名习惯）记入 `run.json`：数量的进 `limits`，其余进 `consent.note`。执行全程遵守，事后可查。

## 本阶段禁止

- 回答问题，哪怕是提纲式回答。
- 把多个行为者、地区、时段、维度捆进一张卡。
- 分叉只写在 `plan.md` 散文里而 `decisions[]` 空着——描述过的分叉什么也没开。
- 为了让决策显得平衡而编造选项。
- "省一轮"而亲自做研究员的任务。分工的要点正是让你的上下文留给阅读。
- 审批开启时，未经用户同意就开工。
