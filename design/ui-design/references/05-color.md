# 配色

> 教材第 5 章。规则编号 `§5.x` 对应 *Refactoring UI* 原书章节。

## §5.1 用 HSL 思考，不用 HEX

HEX 无法表达「更深一点」「更饱和一点」。HSL 可以：

```
hsl(色相 0-360, 饱和度 0-100%, 明度 0-100%)
```

- **色相**决定是什么颜色
- **饱和度**决定有多鲜艳
- **明度**决定有多亮

调色时只动一个轴，其他两个锁定。这比在取色器里拖来拖去可控得多。

## §5.2 色阶算法（教材核心）

一个品牌色需要 9–11 档明度。手挑会得到一套不协调的色阶——有的偏黄，有的偏灰。

教材算法（`scripts/generate_palette.py` 实现了它）：

1. **定基准 500**：这是你的品牌色本身。
2. **定两端 900 / 100**：向黑/白推进时，**饱和度上升**，色相微调。
   - 变暗时色相向 0/120/240（红/绿/蓝主色）偏
   - 变亮时色相向 60/180/300（黄/青/洋红）偏
   - 色相旋转上限 **20–30°**，超过就不像同一个颜色了
3. **定中间 700 / 300**：在 500 与两端之间取中点，同样带饱和度补偿。
4. **填充 800 / 600 / 400 / 200**：按明度线性插值，饱和度跟随相邻档趋势。

**为什么需要饱和度补偿**：纯数学插值到深色端会产生「发灰发死」的深色，到浅色端会产生「发粉发脏」的浅色。人眼在极端明度下感知饱和度会下降，所以必须人为提高。

**不变量**：色相旋转不超过 30°；同一色阶内明度单调。

## §5.3 中性色：暖或冷，不要纯灰

纯中性灰（`hsl(0 0% 50%)`）在界面上显得生硬、像线框图。给中性色一个**极低的饱和度**（2–8%）和一个统一色相：

```
暖中性（偏米/棕）：hsl(30 6% x%)    适合：编辑、生活、消费品
冷中性（偏蓝/青）：hsl(220 8% x%)   适合：技术、金融、企业
偏绿中性：        hsl(150 4% x%)    适合：健康、可持续
```

整套灰阶用同一个色相，只变明度。混用暖冷中性是「看起来脏」的常见原因。

## §5.4 色彩预算：一个主色，两三个辅助，一个危险色

| 角色 | 数量 | 用法 |
|---|---|---|
| 主色（primary） | 1 | 主行动、品牌标记、焦点环 |
| 辅助色（accent） | 1–2 | 强调、数据可视化、状态 |
| 语义色 | 3 | 成功 / 警告 / 危险，各一档 |
| 中性色阶 | 1 套 | 背景、表面、文字、边框 |

主色在页面上出现的面积应该很小——经验值 **不超过 10% 的像素**。主色出现太多，就不再有强调作用。

## §5.5 深色模式不是反色

把亮色主题的 `#fff` 换成 `#000`、`#000` 换成 `#fff`，得到的是一个刺眼、发灰、阴影失效的界面。

正确做法：

- **背景不用纯黑**：`#0a0a0b` / `#111214` 这类带一点色相的黑更柔和，也让表面层次有空间。
- **表面色用亮度差，不用阴影**：深色下阴影几乎看不见，改用「表面比背景亮 3–6%」来分层。
- **主色要降饱和**：亮色下鲜艳的主色放到深色上会发光刺眼，降 10–20% 饱和度。
- **文字不用纯白**：`#e8e9ea` 比 `#fff` 舒适，纯白在深色上会「光晕」。
- **边框用半透明白**：`rgba(255,255,255,0.08)` 能自动适配不同表面色。

## §5.6 三档正文色

正文只用三档文字颜色，多了就没有层级意义：

| 档位 | 用途 | 对比度要求 |
|---|---|---|
| 主文字 | 标题、正文 | ≥ 4.5:1（AA 必需）；≥ 7:1 是 AAA 目标，不是门槛 |
| 次要 | 说明、辅助信息 | ≥ 4.5:1 |
| 三级 | 时间戳、元数据、禁用态 | ≥ 3:1（且不承载关键信息） |

**不变量**：正文颜色不超过三档。

三级色低于 4.5:1 是可接受的**前提**是它不承载用户必须读到的信息。一旦它承载了（比如空状态的主文案），就是缺陷——RED 基线审计里的 P1 就是这一类。

## §5.7 对比度：数值，不是感觉

WCAG 阈值：

| 内容 | 最低 | 建议 |
|---|---|---|
| 正文（< 18.66px 常规 / < 24px 粗体） | 4.5:1 | 7:1 |
| 大文本（≥ 18.66px 常规 / ≥ 24px 粗体） | 3:1 | 4.5:1 |
| 图标、边框、图形元素 | 3:1 | 4.5:1 |
| 焦点环 | 3:1 | 4.5:1 |

用 `scripts/check_contrast.py` 算，不要用在线工具一个个贴——审计时要算几十对。

**半透明要算复合后的实际颜色**：`opacity: 0.45` 的 `#111` 在 `#fff` 上的实际对比度是 1.33:1，不是 `#111` 的 17.7:1。这是审计中最容易漏的一类。

## §5.8 不要只用色相区分

这一条与原书 §5.7（不要只靠颜色）和 `02-hierarchy.md` §2.9 是同一原则。§2.9 是它在「信息分级」语境下的重编号；本节只补配色层面的操作：
数据可视化里，即使色盲友好配色（如 viridis），也要给系列加形状或直接标注。

## §5.9 渐变

> **扩展规则**：原书 §5.9 是「Greys don't have to be grey」之外的空白区，本节的渐变规则
> 来自实践（Linear/Vercel 一类产品），不是原书内容。原书的背景装饰在 §8.3。

- 渐变两端**色相要接近**。红到蓝的渐变中间会经过灰紫，很脏。
- 想做出「有质感」的渐变，让两个端点同色相、不同明度和饱和度。
- 大面积渐变背景要有噪点或纹理，否则会有色带（banding）。
- 不要用渐变做文字填充，除非它是这个页面的唯一视觉焦点。

## 快速自检

1. 色阶是否由算法生成？色相旋转是否 ≤ 30°？
2. 中性色是否带统一色相（不是纯灰）？
3. 主色占页面面积是否 < 10%？
4. 深色模式是否重新设计了表面层次，而不是反色？
5. 正文颜色是否 ≤ 3 档？
6. 所有文字/背景对是否算过对比度？半透明的算过复合值吗？
7. 渐变两端色相是否接近？
