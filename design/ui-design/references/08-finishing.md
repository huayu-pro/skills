# 收尾与空状态

> 教材第 8 章。规则编号 `§8.x` 对应 *Refactoring UI* 原书章节。

## §8.1 用重色做强调，但只在一处

页面上需要「一个记得住的东西」。可能是一个大色块、一个非常规的排版处理、一个动效、一张图。**只一个**。

第二个出现时，第一个就不是焦点了。Chanel 的说法：出门前照镜子，摘掉一件配饰。

## §8.2 背景不要默认纯白

纯白背景是「没做决定」。给背景一个极轻的色偏或纹理：

- 极浅暖白：`hsl(40 20% 98%)`
- 极浅冷白：`hsl(220 15% 98%)`
- 极细网格：透明度 3%
- 极轻噪点：透明度 2%

这样白卡片放上去才有「浮起」的余地。

## §8.3 边框：少用，用浅

- 优先用留白和背景差分组（`03-layout-spacing.md` §3.4）。
- 需要边框时用极浅色：`rgba(0,0,0,0.06)` 到 `rgba(0,0,0,0.1)`。
- 不要 `#ccc`、`#ddd`——它们太深，会和内容抢注意力。
- 分隔线用 `1px`，永远不要 2px（除非是刻意的粗野主义风格）。

## §8.4 空状态是完整的设计

空状态不是占位符。它是用户在「零数据」这个真实状态下看到的**唯一界面**，所以它需要：

| 要素 | 要求 |
|---|---|
| 说明 | 一句话讲清这是什么、为什么为空。不要写「暂无数据」 |
| 行动 | 一个明确的主按钮，指向能产生第一条数据的操作 |
| 视觉 | 可选。一个简单的图形或图标，不要插图集 |
| 隐藏 | 此时无意义的控件必须隐藏：筛选器、搜索框、空表格表头、分页 |

**RED 基线里最严重的缺陷就是这个**：一个空项目列表页，渲染了禁用的筛选器、禁用的搜索框、只有表头的空表格，正文写着「No results found.」，页面上零个可聚焦元素。用户唯一的结论是「应用坏了」。

正确版本：标题「还没有项目」+ 一句说明 + 一个实心主按钮「创建第一个项目」。没有筛选器，没有表格。

## §8.5 加载状态

- **< 200ms**：不显示任何加载指示（闪一下更糟）。
- **200ms–1s**：骨架屏，形状与真实内容一致。
- **> 1s**：骨架屏 + 进度信息（不是转圈）。
- **> 10s**：可取消 + 说明在做什么。

骨架屏的形状必须匹配最终内容，否则加载完成时会有跳动。

## §8.6 错误状态

错误信息必须回答三个问题：

1. 发生了什么（具体，不是「出错了」）
2. 为什么（如果知道）
3. 现在能做什么（一个动作）

```
✗  操作失败
✓  保存失败：网络连接中断。检查网络后重试。
✓  这张图片超过 10MB 上限，请压缩后再上传。
```

**不要道歉**（"抱歉，出了点问题"），不要卖萌，不要模糊。

## §8.7 组件不要照搬库的默认样式

组件库的默认样式是「能用的最低标准」，不是设计。至少改这几处：

- 按钮高度与圆角与整体系统一致
- 输入框的边框色与焦点环
- 卡片的内边距
- 徽章的配色与字号

**不要**改的是：语义结构、可访问性属性、键盘行为。

## §8.8 最后 5% 的细节

这些是「看起来专业」和「看起来像模板」的分界线：

- 焦点环（`:focus-visible`）设计过，不是浏览器默认
- `::selection` 背景色与主色协调
- 滚动条样式（如自定义）
- 空链接、破图、404 都有设计
- 数字用 tabular-nums 对齐
- 过渡时长统一（150–250ms），缓动统一
- 深色模式下的所有状态都验证过

## 快速自检

1. 页面上有几个「记得住的东西」？（应该只有 1 个）
2. 背景是否纯白？有没有给一点点色偏？
3. 边框颜色是否都在 10% 透明度以内？
4. 空状态是否隐藏了无意义控件、提供了主行动？
5. 加载/错误状态是否设计了？
6. 焦点环是否自定义？
7. 组件是否只是库的默认样式？
