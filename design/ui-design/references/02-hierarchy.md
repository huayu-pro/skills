# 视觉层级

> 教材第 2 章。规则编号 `§2.x` 可追溯到 *Refactoring UI* 原书；本文件是按可执行性重写的版本，不是原文转载。

## 为什么先讲这个

界面看起来「像设计过的」还是「像草稿」，90% 取决于一件事：**重要性是否可见**。颜色、圆角、阴影都救不了一个所有元素权重相同、读者不知道先看哪的页面。

所以任何排版问题之前，先解决层级。层级错了，后面每一层的判断都会跟着错——一个间距问题往往只是层级没定清楚的表层症状。

## §2.1 层级即工作本身

把内容按重要性分成三档，并且**在视觉上让这三档确实看起来不同**：

| 档位 | 视觉预算 |
|---|---|
| 主要 | 最大字号或最深颜色或唯一的重色块，三者至少占两个 |
| 次要 | 中等字号，正文色，正常字重 |
| 三级 | 小字号，次要灰色，可以更小但不要低于 12px |

反面症状：三档内容用同样的 16px / #333 / 400，靠读者自己理解业务逻辑去排序。这就是「看起来像后台原型」的根本原因。

**操作**：写代码前，先在注释里列出每个区块的档位。没列出来就不要开始写标签。

## §2.2 字号不是唯一的杠杆

新手把所有层级差异都压在 `font-size` 上，结果要么字号跨度过大（页面像报纸），要么挤在 14/16/18 里分不出来。

四个杠杆，按性价比排序：

1. **字重**——400 与 600 的差别，比 16px 与 18px 的差别明显得多。UI 正文永远不要低于 400。
2. **颜色**——深灰 / 中灰 / 浅灰三档，能承担几乎全部层级，而且不改变排版节奏。
3. **字号**——留给真正的结构级差异（页面标题 vs 区块标题 vs 正文），不要用来做微调。
4. **大小写与字距**——只用于标签类短文本，不要用于句子。

**不变量**：字重只用两档（400/500 与 600/700）；正文颜色最多三档。

## §2.3 深色背景上不要用灰色文字

这是最常见、也最容易被误认为「高级」的错误。在深色或彩色背景上，用 `rgba(255,255,255,0.6)` 或 `#888` 做次要文字，结果是发灰、发脏、像禁用态。

想要的是**降低对比**，不是**降低灰阶**。做法：取背景色的色相，提高饱和度，调整明度到刚好低于主文字。

```
背景 #1a2b4a（深蓝）
✗ 次要文字 #9aa0a6（中性灰，看起来脏）
✓ 次要文字 #8fa8cc（同色相，低明度差，看起来是同一个材质）
```

`rgba(255,255,255,0.x)` 只在一个情况下可用：白色半透明叠在**图像**上，因为图像本身有色彩变化。

## §2.4 强调靠削弱别人

主按钮不够突出时，人的本能是把它做得更大更亮。这会让整页一起变吵。

**先削弱竞争对手**：把旁边那个次要按钮从描边实心改成纯文字，把卡片边框去掉，把标题的次级信息降一档。主按钮不动，它就自然突出了。

这条规则解释了为什么「加粗加亮」型的修改总是让界面更糟：它提高了整体噪声底噪，而人的注意力是相对的。

## §2.5 标签是最后手段

原书 §2.5.3 的结论是「标签是次要的，值是主要的」。

### 标签与值

一组「标签 + 值」的配对里，**标签是次要的，值是主要的**，即使标签写在前面。视觉权重必须反映这一点，否则读者要花力气去找值在哪。

```
✗  Name         Acme Corp
   Plan         Growth
   Seats        12

✓  Name         Acme Corp
   Plan         Growth
   Seats        12
   （标签：13px / 次要灰 / 500；值：15px / 主文字 / 500）
```

同样的逻辑适用于表格表头、表单 label、统计卡片的单位。

## §2.6 语义与视觉分离

`<h1>` 是文档结构决定，不是字号决定。一个页面可以有多个视觉上很小的 `<h2>`（比如侧栏的「筛选」），也可以有一个视觉上很大但不是标题的 `<p>`（比如营销大标语）。

**反向错误**：为了让某个标题变小而把它降级成 `<div>`，破坏文档大纲。正确做法是保留语义标签，用 class 控制外观。

区块标题通常表现得像**标签**而不是标题——小、字重中等、可以有字距。只有页面主标题和极少数强调区块才需要大字号。

## §2.7 平衡字重与对比

字重和对比可以互相补偿：轻字重的文字可以用更深的颜色获得同等分量，重字重的文字可以用更浅的颜色避免过重。

`§2.7.1` 用对比补偿字重（小字号 + 深色 + 400，比大字号 + 浅色 + 500 更安静）。`§2.7.2` 用字重补偿对比（深色背景上 600 + 中等亮度，比 400 + 纯白更稳）。

## §2.8 语义是次要的

一条行动是否「重要」由**层级**决定，不由它的语义类别决定。

一屏之内：

- **一个**主行动（实心、高对比、最大触达面积）
- **少数**次行动（描边或浅底）
- **若干**三级行动（纯文字链接）

破坏这条的最常见方式：页面上有三个实心按钮，读者不知道哪个是「继续」。

`§2.8.a` 三种处理：实心（主）、描边（次）、纯文字（三级）。

`§2.8.1` 危险操作不因危险而变大。删除不需要大声，它需要**明确**——红色文字、二次确认、位置分离，都比「做成红色实心大按钮」好。把删除做成最响的元素，会让真正的主行动失去注意力。

`§2.8.2` 破坏性操作不放在主行动旁边。至少隔一个视觉分组，或用不同的交互模式（长按、输入确认）。

## §2.9 不要用颜色独自承载信息

> **扩展规则**（原书 §5.7 是同一原则的出处；本 skill 在层级语境下重编号为 §2.9，
> 因为它是「信息分级」问题而非配色问题。引用原书时请用 §5.7。）

红色表示错误、绿色表示成功，只在同时有文字、图标或位置差异时才成立。色盲用户（约 8% 男性）看不到你的色相差别。

具体做法：错误提示写清楚「邮箱格式不正确」而不只是一个红框；成功状态配一个对勾；数据图表用形状或直接标注区分系列。

**注意**：涨跌数据用红绿是行业惯例，但必须同时有符号（+/-）或箭头。`📉 2.1%` 配绿色是自相矛盾的——emoji 说跌，颜色说好。

## 快速自检

回答不出下面任何一条，说明层级没做完：

1. 这一屏最重要的一个元素是什么？它在视觉上是不是最突出的？
2. 次要内容能不能在不看文字的情况下被识别为次要？
3. 主行动是哪一个？它旁边有没有同权重的竞争者？
4. 深色/彩色背景上的次要文字，是不是同色相降明度得到的？
5. 每个视觉层级差异，用的是哪个杠杆（字重/颜色/字号/字距）？
