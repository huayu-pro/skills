# 设计原型库

## 这是什么

`assets/patterns/` 里的卡片是从 One Page Love 目录 **550 条**中成功抽取 token 的 **412 个站点**里，取 **379 个有可用 token 的**做聚类得到的**设计原型**。

> 这三个数字必须分清：**550 = 目录条数**（分层抽样得到），**412 = 双引擎抽取成功数**（可抽站点里 91%），**379 = 有 ≥3 个颜色 token、能参与聚类数**。任何声称「550 个站点蒸馏」的说法都是虚高。每张卡包含：

- token 区间（字阶比值、饱和度、明度跨度、间距基数）
- 常见 section 顺序（来自 One Page Love 的人工分类）
- 高频颜色
- 代表站名（只作风格锚点，不含 URL）
- 样本量与置信度

## 为什么要有它

规则层能告诉你「不要用灰字压彩色背景」，但不能告诉你「一个暗色的技术产品页面，主色饱和度应该在什么范围」。

原型库回答后一类问题。它把「设计品味」从模糊的感觉变成**可查的区间**。

## 关键限制（必须说清）

**这是统计归纳，不是设计真理。**

1. **样本决定可信度**。样本 < 15 的原型标注「低置信度」，不要当作规范。
2. **聚类按视觉特征，不按行业**。一个原型里可能同时有餐厅和 SaaS——它们的明暗、饱和度、字阶接近，但题材完全不同。
3. **区间不是目标值**。抄中位数会得到一张「像这个原型、但不属于你项目」的页面。取区间，让题材决定落点。
4. **语料有偏**。One Page Love 是单页营销站的策展画廊，长于落地页、作品集、产品发布，短于后台/数据密集型界面。做管理后台时，原型库的参考价值明显下降，应更多依赖规则层。

## 检索

```bash
# 全部原型
python3 scripts/query_corpus.py --list

# 按特征筛（评分排序，不硬过滤）
python3 scripts/query_corpus.py --style minimal --genre saas
python3 scripts/query_corpus.py --color dark --mood vivid
python3 scripts/query_corpus.py --mood tight --limit 5

# 读一张卡
python3 scripts/query_corpus.py --id arch-b63c5c   # 用 --list 查真实 ID

# 语料整体统计
python3 scripts/query_corpus.py --stats
```

**查询是评分不是过滤。** 如果没有任何原型得分超过阈值，脚本会明确输出「无匹配原型」——这时按 SKILL.md 的要求走自由方向，并在约束简报里写出自己的 token 系统。**不要**硬套一个不匹配的原型。

## 卡片怎么读

以一张真实的卡为例（`arch-1a1b08`，样本 38，是库里中等规模的一类）：

```markdown
# 浅色低饱和·minimal
浅色界面，低饱和配色，单色相，常规字阶，平面表面。样本 38 个站点。

**样本量**：38 个站点　**置信度**：中

## Token 区间
| 维度 | 中位数 | 25% | 75% |
|---|---|---|---|
| 字阶比值 | 1.18 | 1.12 | 1.23 |
| 字号档位数 | 12 | 6 | 18 |
| 主色最大色度 | 3 | 0 | 12 |
| 调色板明度跨度 | 100% | 100% | 100% |

**间距基数**：4.0px（18/38 个站点）
```


读法：

- **字阶比值 1.12–1.23** → 这个原型的字阶是紧的。用 1.4（像报纸）会明显偏离。
  注意这与 `04-typography.md` §4.1 的 1.2 下限有张力：**层级清晰优先于统计常见**，
  下限是硬要求，原型的 IQR 只是参考。
- **字号档位 6–18**（中位 12）→ 这个原型用的是多档细调，不是 4 档粗分。
- **主色最大色度 0–12** → 这是**单色/近灰**原型：主色几乎不带色相。
  别在这里找一个「品牌色」——它本来就没有。`#5e6ad2`（色度约 55）属于另一个原型。
- **明度跨度 100%** → 调色板从纯黑到纯白都有，对比是结构性的，不是靠一个强调色撑起来的。

## 与品牌语料的分工

| 资源 | 回答什么 | 位置 |
|---|---|---|
| **原型库**（本文件） | 「这类页面通常怎么设计」——统计规律 | `assets/patterns/` |
| **品牌语料** | 「某个具体产品怎么设计」——一套完整 token | `assets/brands.json`、`references/19-brand-index.md` |

用法差异：原型库给**区间**，品牌语料给**实例**。定方案时先用原型库收窄方向，再用 2–3 个品牌语料看具体值是怎么落的。

## 附加分析

- `assets/patterns/patterns.md#techniques`：405 个站点的**代码级**布局/组件实测（列宽、gap、圆角、字号），用于回答「这个值通常是多少」。
- `assets/patterns/patterns.md#deep`：343 个站点的设计系统深读（间距、字阶、表面、动效），用于回答「这类站点的系统怎么搭」。
- 两者都是统计归纳，不是规范；取区间，不抄中位数。

## 强制使用

SKILL.md 的 Workflow B 第 0 步要求：写代码前必须调用 `query_corpus.py` 选定一个原型（或明确声明无匹配），并在产出文件首行的约束简报注释里写下原型 ID。

Workflow D 审计时检查成品是否偏离该原型的 token 契约（明暗、饱和度、字阶比值、间距基数）。偏离即 P1，除非简报明确要求偏离。

## ID 是稳定的

原型 ID 由内容哈希生成（`arch-` + 6 位），不是序号。重新聚类后同一组站点仍得到同一个 ID，
所以写进 DESIGN BRIEF 的 ID 不会在语料扩充后静默指向另一张卡。这一点在 v1.0.0 修正过：
早期版本用位置编号，重跑后 `archetype-01` 会从「暗色技术产品」变成「浅色极简」。

## 语料的重新生成

原型库是**构建期产物**，不在运行时重新生成。本包只带蒸馏后的 14 张卡与
`archetypes.json`；原始语料（550 目录 / 412 抽取 / 379 聚类）不随包分发。

- 抽样与聚类口径：见构建区 构建记录 `SOURCE-LEDGER` 与 `ui-design-v4/reports/`。
- 重新生成需要工作区的 `corpus/` 与 `build/pipeline/`；普通使用者不需要。
- seed 固定为 20261107，输入按 slug 排序。同样的语料产出同样的原型。
- 原型 ID 是内容哈希，不是序号；语料扩充不会静默改指。
