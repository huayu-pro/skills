# 深度与阴影

> 教材第 6 章。规则编号 `§6.x` 对应 *Refactoring UI* 原书章节。

## §6.1 光从上方来

这是深度的唯一物理依据，所有其他规则都从它推导：

- **凸起（raised）**：顶部边缘更亮 + 下方有短而清晰的阴影
- **凹陷（inset）**：顶部内部有阴影 + 底部边缘更亮

```
凸起按钮：
  border-top: 1px solid rgba(255,255,255,0.15)   ← 顶边受光
  box-shadow: 0 1px 2px rgba(0,0,0,0.12)          ← 短促阴影在下方

凹陷输入框：
  box-shadow: inset 0 1px 2px rgba(0,0,0,0.08)    ← 内部顶部阴影
  border-bottom: 1px solid rgba(255,255,255,0.6)  ← 底边受光
```

**不变量**：阴影偏移量 `y > 0`。`y = 0` 的阴影（纯模糊扩散）在物理上不存在，会让元素看起来像发光而不是浮起。

## §6.2 阴影是组合，不是单个

真实的阴影由多个光源距离产生，所以是**多层叠加**：

```css
/* 单一阴影：扁平、假 */
box-shadow: 0 4px 8px rgba(0,0,0,0.15);

/* 多层：近处锐利 + 远处柔和 */
box-shadow:
  0 1px 2px rgba(0,0,0,0.06),
  0 2px 4px rgba(0,0,0,0.06),
  0 4px 8px rgba(0,0,0,0.04);
```

规律：

- 近层：小 blur、小 offset、高不透明度
- 远层：大 blur、大 offset、低不透明度
- 层数 2–4 层足够

**阴影颜色不要用纯黑**：用主色或中性色的深色版，`rgba(30,41,59,0.12)` 比 `rgba(0,0,0,0.12)` 更自然。

## §6.3 五个层级就够

| 层级 | 用途 | 阴影强度 |
|---|---|---|
| 0 | 页面背景 | 无 |
| 1 | 卡片 | 极轻，几乎只有边框感 |
| 2 | 悬停卡片、下拉菜单 | 轻 |
| 3 | 模态、抽屉 | 中，且带背景遮罩 |
| 4 | Toast、工具提示 | 强，浮在最上层 |

**不变量**：层级不超过 5 档。层级多了，读者分不清哪个更「上层」，深度就失去了意义。

## §6.4 深色模式下阴影失效

深色背景上，黑色阴影几乎不可见。替代方案：

1. **表面亮度差**——表面比背景亮 3–8%，这是深色模式的主要分层手段。
2. **边框**——`1px solid rgba(255,255,255,0.06~0.12)`。
3. **轻微阴影仍保留**——它在大面积（模态）上仍有效，只是不能作为唯一手段。

## §6.5 不要用阴影做装饰

「加个阴影让它看起来有层次」通常导致所有元素都浮起，结果没有东西浮起。

阴影只回答一个问题：**这个元素相对页面是凸起还是凹陷**。答不出来就不要加。

## §6.6 边框与阴影的替代关系

一个元素要跟背景分开，三选一，不要同时用：

| 手段 | 何时用 |
|---|---|
| 边框 | 元素与背景同色，需要清晰边界（表格、输入框） |
| 阴影 | 元素需要「浮起」（卡片、菜单、模态） |
| 背景色差 | 元素是内容容器，不需要强调边界（区块、面板） |

同时用边框 + 阴影 + 背景差，是「廉价感」的主要来源之一。

## 快速自检

1. 所有阴影的 `y` 偏移是否 > 0？
2. 阴影是否至少 2 层？
3. 阴影颜色是否带色相（不是纯黑）？
4. 层级是否 ≤ 5 档？
5. 深色模式是否用了表面亮度差？
6. 有没有元素同时用了边框 + 阴影 + 背景差？
