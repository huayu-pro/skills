# 排版

> 教材第 4 章。规则编号 `§4.x` 对应 *Refactoring UI* 原书章节。

## §4.1 字阶：用比值，不要用直觉

手挑字号（16/18/22/28/34）会产生一套没有内在关系的数字，读者感觉不到节奏。用比值生成：

| 用途 | 比值 | 从 16px 起 |
|---|---|---|
| 紧凑型 UI（仪表盘、后台） | 1.2 | 13.3 · 16 · 19.2 · 23 · 27.6 |
| 常规产品界面 | 1.25 | 12.8 · 16 · 20 · 25 · 31.25 |
| 营销页 / 编辑型 | 1.333 | 12 · 16 · 21.3 · 28.4 · 37.9 |

**不变量**：相邻两档比值不低于 1.2。低于这个值，两档在视觉上分不开，等于白设。

> **与语料的一个张力，值得知道**：379 个真实站点抽出来的字阶比值中位数是 **1.154**
> （IQR 1.119–1.200），也就是说**大多数真实站点的字阶比 1.2 更密**。原因有两个：
> 一是这些站点的字号很多来自组件库默认值（Tailwind 的 `text-sm/base/lg` 比值约 1.125），
> 不是刻意设计的；二是抽取值里混入了行内小元素（徽章、脚注）的字号。
>
> 这条 1.2 的下限因此不是「统计上最常见的做法」，而是「能形成清晰层级的最低要求」。
> 两者冲突时，**层级清晰优先于统计常见**。如果你的项目已经有一套 1.15 的字阶并且层级可读，
> 不要为了符合这条规则去重做它——报告冲突，让用户决定（见 SKILL.md 作用域守则）。

实操：取 5–7 档就够。多了会产生「这个 17px 和那个 18px 有什么区别」的问题。

## §4.2 字体选择

**数量**：一个或两个。两个时必须明显不同（衬线 + 无衬线，或几何 + 等宽），不能是 Inter + Roboto 这种同类。

**配对逻辑**：让两个字体承担不同**角色**，而不是不同**风格**。

```
标题：高对比衬线（Editorial / Playfair）    正文：中性无衬线（Inter / Söhne）
标题：几何无衬线（Poppins）                 正文：人文无衬线（Source Sans）
全部：单一可变字体，用字重和宽度做区分       ← 最安全，也最容易做得好
```

**不要**：用系统默认栈却不做任何排版决策。`font-family: system-ui` 不是选择，是弃权。如果确实要用系统字体，就明确说「这是刻意的性能/一致性决策」，并且把字距、行高、字重调到位。

**可变字体优先**：一个 `font-variation-settings` 能覆盖 300–800 全档，比加载四个静态字重更轻。

## §4.3 行宽 45–75 字符

正文行宽用 `ch` 或 `em` 控制，不要用 `px` 猜。

```css
.prose { max-width: 65ch; }        /* 常规正文 */
.prose--wide { max-width: 75ch; }  /* 宽一点，行高要跟上 */
```

- 窄于 45 字符：换行过频，阅读节奏碎
- 宽于 75 字符：眼睛回扫时容易串行
- 衬线字体可以到 75，无衬线建议 65
- 大标题不受此限（标题本来就不连续阅读）

**不变量**：正文 45–75 字符。低于或高于都是缺陷。

## §4.4 行长与行高的联动

行高不是固定值，它随行长和字号变化：

| 情况 | line-height |
|---|---|
| 长行（70+ 字符） | 1.6–1.75 |
| 常规行（45–65 字符） | 1.5–1.6 |
| 短行（< 45 字符，如卡片） | 1.4–1.5 |
| 大标题（> 32px） | 1.0–1.15 |
| 巨型展示字（> 64px） | 0.9–1.05 |

原理：行长越长，眼睛回扫的路径越长，越需要更大的行间空隙来锚定。字号越大，字形本身占据的垂直空间越多，相对行高应该越小。

**不变量**：正文行高不低于 1.4；大标题行高不高于 1.2。

## §4.5 字距：只在两端用

`letter-spacing` 只在两种情况有意义：

1. **大字号标题**：负字距（-0.01em 到 -0.03em），因为大字号下默认字距显得松散。
2. **小字号全大写标签**：正字距（0.02em 到 0.08em），因为大写字母间距天然紧。

正文不要动字距。中文字体不要用负字距（会挤压笔画）。

## §4.6 对齐：左对齐是默认

- **左对齐**：几乎所有正文、列表、表单。中文和英文都适用。
- **居中**：只用于短文本（1–2 行），如空状态、营销标语、模态标题。三行以上的居中文本是阅读障碍。
- **右对齐**：只用于数字列（金额、统计），让小数点对齐。
- **两端对齐**：只用于窄栏且已有连字符支持的排版。Web 上慎用，中文两端对齐会拉出难看的字间空隙。

## §4.7 字重的纪律

- 正文 400
- 强调/标签 500
- 标题 600
- 极少数展示字 700+

**不要用 300 做正文**（细字在小字号下笔画消失，尤其在非 Retina 屏）。**不要在同一个视觉层级里混用 500 和 600**——读者分不出，只会觉得不一致。

## §4.8 数字排版

- 表格、价格、统计里的数字用 `font-variant-numeric: tabular-nums`，否则列不对齐。
- 大数字（统计卡片）可以单独配一个展示字体，但要在同一行内保持基线一致。
- 单位（`/mo`、`%`、`ms`）用比数字小一档的字号 + 次要色，不要和数字同权重。

## §4.9 中文排版补充

教材是英文语境，以下是中文必需但原书未覆盖的：

- **中西文间距**：中文与英文/数字之间加 1/4 em 空隙。手写 `margin` 或用 `text-spacing-trim`（支持度有限），实际项目里通常在文案层加空格。
- **标点挤压**：避免行首出现 `，。、；：`。用 `hanging-punctuation: first`（支持有限）或接受默认。
- **行高**：中文比英文需要更大行高，正文建议 1.6–1.8（英文 1.5–1.6）。
- **字重**：中文字体的 500 和 600 差异往往不明显，层级优先用字号和颜色。
- **不要用负字距**，会让笔画粘连。

## 快速自检

1. 字阶是否由比值生成？相邻档比值是否 ≥ 1.2？
2. 正文行宽是否在 45–75 字符？
3. 行高是否随行长和字号变化？
4. 字体数量是否 ≤ 2？两个字体是否角色不同？
5. 三行以上的文本有没有被居中？
6. 数字列是否用了 tabular-nums？
