# 00 · 路由

> 先判断用户在哪一类任务，再决定读哪几章。不要把所有章节都加载一遍；
> 也不要用一个工作流硬套另一个。

## 七个工作流

| 用户要… | 工作流 | 先读 | 退出条件 |
|---|---|---|---|
| 配色、设计系统、token、字体/间距刻度 | **A · Tokens** | `05` → `03` → `04` | 五件套齐 + 每个前景/背景对算过对比度 |
| 新页面、屏幕、组件、落地页 | **B · Build** | `01` → 相关规则镜 → `21` | 首行有 DESIGN BRIEF；1280/375 看过；`audit.py` 无 P0 |
| 「弄好看点」「看着不对」 | **C · Refine** | `12` → `13` | D 的 P0 全清；P1 清到用户说够 |
| 评审、上线前检查 | **D · Audit** | `12` → `24` | 七镜走完 + 动效三层证据 + `skipped` 列全 |
| 找参考、这个风格怎么落地 | **E · Reference** | `14` → `19` → `25` | 找到可解释的匹配，或明确声明无匹配 |
| 动效设计、加交互、调手感 | **F · Motion** | `09` → `22` → `23` → `24` | 主族 + 1 个注意瞬间 + 参数在簇内 + 运行时验证 |
| 组件库选型 / 某个库怎么写 | **G · Stack** | `18` → `15`/`16`/`17` | 决策树走到一个叶子并给出理由 |

## 混合意图

按顺序跑，并说明你在跑哪几个：

- 「给没有设计系统的应用做设置页」= A → B。
- 「页面太丑，顺便加个动效」= D → C → F。
- 「照这个风格做一个落地页」= E → B → F。
- 「用 HeroUI 重做这个页面」= G → B → D。
- 「动效太多，砍掉一些」= D → F → C。

## 不该用这个技能的时候

- 后端逻辑、数据建模、API 设计。
- 纯文案编辑，没有视觉表面。
- 原生移动端 App（iOS/Android 原生控件）。
- 视频制作/剪辑（用 video-shotcraft）。
- 只需要一张海报/PPT（用对应文档技能）。

## 三条全局纪律

1. **既有系统优先**：项目已有 token/组件库/暗色模式时，翻译成它的词汇；
   不覆盖、不静默迁移、不装用户没要求的依赖。
2. **先结构后装饰**：先内容分级、灰度、间距，再上色、深度、动效。
3. **证据分级**：静态扫描、运行时探针、人工复核分开写；没测就写 `skipped`。

## 强度档位

用户说「快速看一下」→ 只跑 D 的 P0 清单；
用户说「正式评审」→ 七镜 + 动效三层 + 报告；
用户说「从零做」→ A/B/F 全跑。
不要对一句「看看这个按钮」启动完整设计系统流程。

## 输出语言

正文中文；规则 ID、类名、命令、文件路径保持英文/原文。
交付物的语言跟随用户：用户中文就中文，用户英文就英文。
